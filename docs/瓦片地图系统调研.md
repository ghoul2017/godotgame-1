# 瓦片地图系统调研

调研日期：2026-05-27

## 1. 项目需求定位

源依据链中，瓦片地图相关需求来自：

- `docs/原始设计.txt`：地图以“区域”划分，被战争迷雾覆盖；内容以程序生成为主；每次新地形、资源分布、废墟布局不同。
- `docs/整体策划案.md`：第 7 步接入探索、战争迷雾、扫描和区域内容；第 11 步接入程序生成、随机事件和复现调试。
- `docs/5. 地表 RTS 控制与单位系统.md`：移动指令需要地形阻挡和区域边界接口；小地图先做框架，真实迷雾和内容由第 7 步接入。
- `docs/6. 地表矿产、物品物流、建造、生产和电力系统.md`：建筑放置要检查占地、地形和阻挡；矿产点先是正式对象，完整分布由第 7、11 步扩展。

当前没有源依据要求使用六边形地图、外部 Tiled 编辑器或特定瓦片插件。因此后续方案应优先保持可替换：地图权威数据由项目自己的 `ExpeditionState.map_state` / 地表地图服务持有，`TileMapLayer` 主要承担表现、碰撞辅助和编辑器工作流。

## 2. Godot 4.6 原生能力

### 2.1 TileMapLayer 和 TileSet

Godot 4.6 的 `TileMapLayer` 是 2D 瓦片地图节点。官方文档说明它使用 `TileSet` 生成基于网格的地图，旧 `TileMap` 已弃用；一个 `TileMapLayer` 只有一层，需要多层效果时使用多个 `TileMapLayer` 节点。

参考：

- https://docs.godotengine.org/en/4.6/classes/class_tilemaplayer.html
- https://docs.godotengine.org/en/4.6/tutorials/2d/using_tilesets.html
- https://docs.godotengine.org/en/4.6/tutorials/2d/using_tilemaps.html

对本项目的含义：

- 后续应使用 `TileMapLayer`，不要新增旧 `TileMap`。
- `TileSet` 应保存成外部 `.tres` 资源，方便地表场景、调试场景、生成预览和小样地图共用。
- 地表地图建议拆多层：
  - `GroundLayer`：基础地形。
  - `DetailLayer`：裂纹、残骸、装饰、非阻挡细节。
  - `ObstacleLayer`：岩壁、深坑、不可通行边界等视觉阻挡。
  - `StructurePreviewLayer`：建造预览和调试格。
  - `DebugOverlayLayer`：生成、寻路、迷雾和区域调试可视化。

### 2.2 TileSet 自定义数据

Godot `TileSet` 支持自定义数据层。官方文档说明自定义数据绑定在 `TileSet` 的 tile 上，同一 tile 的所有实例共享数据；如果需要同图块不同数据，可使用 alternative tile。

建议预留的 tile 自定义数据：

| 字段 | 用途 |
| --- | --- |
| `terrain_id` | 地形 ID，例如 `dust_plain`、`scrap_field`、`ruin_floor`。 |
| `terrain_tags` | 地形标签，例如 `surface`, `buildable`, `rough`, `hazard`, `ruin`。 |
| `ground_walk_cost` | 地面单位移动权重。 |
| `ground_blocked` | 地面单位是否不可通行。 |
| `flying_blocked` | 飞行单位是否不可通行，通常只用于地图边界或特殊危险。 |
| `build_allowed` | 是否允许建筑占地。 |
| `foundation_required` | 是否需要地基、平台或额外施工。 |
| `vision_blocking` | 是否阻挡视野或扫描线。 |
| `fog_reveal_modifier` | 视野揭示或扫描修正。 |
| `spawn_tags` | 程序生成参考标签，例如可生成废料、矿脉、废墟入口。 |

这些字段只能作为地形和生成规则输入，不能替代矿产点、建筑、地上物、库存或物流订单的权威状态。矿产点仍必须是 `MineralDepositInstance`，建筑仍必须是建筑/施工点实例，道具仍必须在具体库存或地上位置中。

### 2.3 原生 terrain / autotiling

Godot 4 的 terrain 是 Godot 3 autotile 的更强替代。官方文档说明 terrain 是赋给 atlas tile 的属性，TileMap 的地形绘制模式会根据邻接关系智能选择图块；terrain set 支持 Match Corners and Sides、Match Corners、Match Sides。

对本项目的含义：

- 第 7 步之前，只需要少量可读地形和空投点附近可通行区域，不要提前做完整程序生成。
- 第 11 步做程序生成时，可用 `TileMapLayer.SetCellsTerrainConnect` / `SetCellsTerrainPath` 从 C# 批量生成地形。
- 原生 terrain 对完整 tileset 质量要求高：边、角、内角和过渡块缺失会导致自动连接结果不好。美术资源落地时必须按 terrain set 需求准备完整组合。

### 2.4 碰撞、导航和遮挡

Godot `TileSet` 可配置 physics、navigation、occlusion layer。官方文档也提醒，TileMap 内建 navigation 有实际限制；设计完 TileMap 后可考虑烘焙到更优化的 `NavigationRegion2D` 或 `NavigationServer2D`，并且 2D navigation mesh 不能像视觉或物理形状那样层叠，否则可能造成路径合并和逻辑错误。

本项目建议：

- 碰撞层可用于鼠标命中、边界和静态障碍辅助。
- RTS 单位移动不要直接依赖多层 TileMap navigation。地表单位寻路优先使用项目自己的 C# `SurfaceNavigationService`，从地图格、建筑、矿产点和动态阻挡生成 `AStarGrid2D`。
- 视野、迷雾、扫描不要靠 TileMap occlusion 自动解决；第 7 步应有独立的 `FogOfWarState` / 揭示网格，TileMap 只显示结果。

### 2.5 TileMapLayer 坐标限制

Godot 4.6 文档说明 `TileMapLayer` 序列化坐标限制在 16-bit signed integer 范围，即 X/Y 从 `-32768` 到 `32767`，超出会在保存 tile data 时 wrap。

对第 11 步的含义：

- 不要把无限大地图直接写进一个巨大 `TileMapLayer`。
- 地表地图应按 `region` / `chunk` 管理，运行时只实例化或绘制当前远征范围。
- 存档保存应记录种子、区域坐标、已修改 cell 和对象实例，而不是把超大 TileMap 当作唯一地图存档。

## 3. Godot 资源库候选

### 3.1 优先参考或试用

#### A-Star Grid Map

- 链接：https://godotengine.org/asset-library/asset/4950
- 版本信息：2D Tools，Godot 4.4，Community，MIT，0.1.0，2026-03-25。
- 作用：管理 `AStarGrid2D`，可连接 `TileMapLayer` 和动态碰撞体组，自动构建网格并设置 solid points。
- 判断：适合第 5 步或第 6 步做寻路 spike。建议先阅读实现，再决定是否直接引用；若是 GDScript 主导，优先转写为 C# 服务。

#### Grid-based Navigation with AStarGrid2D Demo

- 链接：https://godotengine.org/asset-library/asset/2723
- 版本信息：Demos，Godot 4.2，Featured，MIT。
- 作用：官方 AStarGrid2D 示例，包含 2D 网格寻路和平滑移动。
- 判断：作为学习资料优先级很高，不建议直接导入运行时。

#### Better Terrain

- 链接：https://godotengine.org/asset-library/asset/1806
- 版本信息：2D Tools，Godot 4.3，Community，Unlicense，1.1，2026-02-14。
- 作用：替代 Godot 4 `TileMapLayer` terrain 系统，规则更灵活，提供代码应用和更新 terrain 的 API。
- 判断：如果原生 terrain 在第 7 或第 11 步暴露出 tileset 配置复杂、过渡块难维护、程序生成难控的问题，再做试用。当前不要提前接入。

#### TileMapDual

- 链接：https://godotengine.org/asset-library/asset/3877
- 版本信息：2D Tools，Godot 4.4，Community，MIT，5.0.2，2026-05-02。
- 作用：实时 dual-grid tileset 系统，宣称可把常见 47 tile 需求降到 15 tile。
- 判断：对荒地、岩壁、废墟边界这类大面积自然过渡可能很有用。风险是自定义 TileMapLayer 节点可能影响我们 C# 控制、存档和生成调试。建议作为美术产能不足时的候选，不作为默认架构。

#### YATI (Yet Another Tiled Importer) for Godot 4

- 链接：https://godotengine.org/asset-library/asset/1772
- 版本信息：2D Tools，Godot 4.3，Community，MIT，2.2.7，2026-03-20。
- 作用：导入 Tiled Map Editor 的 `.tmx`、`.tmj`，支持多种层、对象、方向、翻转旋转、碰撞、动画、自定义数据和属性；资源库页说明可查看仓库获取 C# 或 runtime 版本。
- 判断：如果后续决定用 Tiled 做手工废墟、教程地图或测试地图，可试。程序生成和运行时权威状态仍应在项目内，不要让 Tiled 文件成为远征存档来源。

### 3.2 后期候选

#### Wave Function Collapse (WFC)

- 链接：https://godotengine.org/asset-library/asset/1951

#### Fast Wave Function Collapse (WFC)

- 判断：如果 WFC 成为性能热点，可评估。但 C++ 插件会增加导出和平台风险；先用纯脚本/自研生成规则完成可复现性，再考虑加速。

#### DynamicMinimap

- 判断：可借鉴图标注册和边缘钳制。项目小地图必须和战争迷雾、区域发现、空投点、矿产点状态、单位编组和 RTS 镜头框绑定，直接接入通用小地图插件收益有限。

#### TileMapLayer Baker

- 链接：https://godotengine.org/asset-library/asset/5151

- 判断：后期大地图静态装饰层过多时可试。第 7/11 步早期不应烘焙，因为迷雾、扫描、建造、受损和遗留状态需要可调试的 tile / object 数据。

### 3.3 不建议作为核心依赖

#### Tiled Map Importer for Godot 3

- 链接：https://godotengine.org/asset-library/asset/158
- 判断：只支持 Godot 3.x，不适合 Godot 4.6 项目。若用 Tiled，优先看 YATI。

#### Hexagon TileMapLayer / Hex grid 工具

- 判断：原始设计没有要求六边形地图。六边形会影响寻路、建筑占地、UI 选中、范围显示和美术产能；除非后续设计明确改成六边形，否则不引入。

#### TileMapLayer Collider Generator / Tileset Collision Generator

- 判断：可作为编辑器辅助，但本项目的寻路、建造阻挡和动态建筑占地不能只靠生成碰撞多边形。外部碰撞生成器只能服务静态边界，不能接管 `SurfaceNavigationService`。

#### Generate TileMapLayer from image of tilemap

- 判断：适合从旧素材图反推 TileMapLayer。当前项目没有旧 tilemap 图片迁移需求，暂不需要。

## 4. 推荐架构

### 4.1 权威数据与表现分离

建议后续建立三层：

1. `SurfaceMapState`：存档和权威状态，记录远征 ID、种子、区域、已发现 cell、已修改 cell、tile 语义 ID、区域标记和版本。
2. `SurfaceMapService`：C# 逻辑服务，负责坐标转换、地形查询、建造校验、视野揭示、扫描查询、生成和复现。
3. `SurfaceTilemapView`：Godot 表现层，负责把 `SurfaceMapState` 渲染成多个 `TileMapLayer`，并提供调试覆盖层。

不要让 `TileMapLayer.tile_map_data` 成为唯一地图存档。TileMap 是表现与编辑器资产，权威数据必须能被测试、序列化、差异存档和 seed 复现。

### 4.2 地图 cell 数据建议

后续可以新增类似数据结构：

```text
SurfaceCellState
- coord: Vector2i
- terrain_id: string
- terrain_tags: string[]
- discovered: bool
- visible: bool
- last_seen_revision: int
- generated_region_id: string
- override_tile_id: string
- flags: build_blocked / movement_blocked / vision_blocked / hazard
```

对象不要塞进 cell 里当列表字段的唯一来源。矿产点、废墟、建筑、施工点、地上物、单位仍应有自己的实例表，并用坐标或占地区域引用地图。

### 4.3 寻路建议

- 使用 `AStarGrid2D` 作为首版地面单位寻路核心，因为它有 C# API、支持 partial 2D grid、solid point 和 weight scale。
- `SurfaceNavigationService` 从以下来源构建网格：
  - 地形 cell 的 `ground_blocked` 和 `ground_walk_cost`。
  - 建筑、施工点、防御墙、矿产点等动态阻挡。
  - 当前任务临时预留，如施工区、拥堵点、危险区。
- 飞行单位单独处理：可越过地面阻挡，但仍受地图边界、禁飞区和目标可达性限制。
- 第 5 步只做基础移动和边界，第 6 步接建筑动态阻挡，第 7 步接迷雾未知区策略，第 8 步接威胁绕行。

### 4.4 战争迷雾与小地图

战争迷雾不要直接等同于 TileMap 的可见性。建议：

- `FogOfWarState` 保存已探索、当前可见、最后一次看见的 revision。
- 主视图用 shader、CanvasItem 或覆盖层显示迷雾。
- 小地图读取同一份 `FogOfWarState`，只显示已探索内容；当前可见区域高亮。
- `DynamicMinimap` 可参考图标和边界处理，但项目小地图应自研或深度包装，确保能显示 RTS 镜头框、空投点、单位、矿产点、废墟和扫描信号。

### 4.5 程序生成建议

第 11 步生成顺序建议：

```text
seed
-> 生成区域骨架和风险带
-> 生成基础地形 cell
-> 生成可达性图和空投点安全区
-> 放置矿产点、废墟、危险区和特殊信号
-> 校验火箭链路关键材料可达
-> 写入 SurfaceMapState 和对象实例表
-> 渲染 TileMapLayer
```

WFC 适合局部装饰和废墟形状，不适合作为全局经济和关键路径控制器。关键资源分布必须先满足玩法约束，再交给 tile 表现层铺图。

## 5. 阶段接入顺序

### 第 5 步：地表 RTS 控制与单位系统

- 建立地图坐标转换接口。
- 建立 `SurfaceNavigationService` 最小版本。
- 用 `AStarGrid2D` 支撑地面移动。
- `TileMapLayer` 可只提供首个调试地形层和地图边界。

### 第 6 步：矿产、物流、建造、生产、电力

- 建筑放置校验读取地形 tag、占地和动态阻挡。
- 建筑确认后更新动态阻挡，不直接改经济库存。
- 矿产点仍是独立实例，只在地图上有坐标和视觉节点。
- 施工点、仓库、建筑输入 / 输出可在地图上定位。

### 第 7 步：探索、迷雾、扫描、区域内容

- 建立正式 `FogOfWarState`。
- 小地图接入探索状态。
- 区域、废墟、特殊信号和隐藏矿产由地图/对象生成服务统一创建。
- TileMapLayer 增加迷雾、扫描反馈和区域标记表现。

### 第 11 步：程序生成、随机事件和复现调试

- 正式建立 seed 生成管线。
- 引入 chunk / region 概念，避免超大 TileMapLayer 坐标和存档问题。
- 加入生成调试覆盖层：地形、可达性、资源分布、风险、迷雾、建筑阻挡。
- 需要时试用 Better Terrain、WFC 或 TileMapDual，但插件不得接管权威地图和对象状态。

## 6. 推荐下一步

1. 第 5 步实现前，先做 `AStarGrid2D` C# spike：输入一组 `SurfaceCellState`，输出可移动路径、失败原因和调试路径线。
2. 第 6 步实现前，定义 `terrain_tags_allowed` / `terrain_tags_blocked` 与建筑占地校验的关系。
3. 第 7 步策划时，单独写 `docs/7. 探索、战争迷雾、扫描和区域内容.md`，把 `FogOfWarState`、小地图、区域内容和 TileMapLayer 分层写清楚。
4. 第 11 步前，再评估 Better Terrain、WFC 和 TileMapDual 是否值得接入；现在只记录，不安装。
