# 第一步策划案：基础工程、输入和场景流程

## 1. 目标定位

第一步要建立游戏的运行骨架。项目使用 Godot 4.6 .NET，运行时代码默认使用 C#。本阶段不负责实现具体玩法数值，但必须按最终游戏结构搭好入口、场景、输入、全局数据流和调试通道，保证后续轨道站、地表远征、回归结算、序章叙事都能接入同一套流程。

本阶段完成后，项目应具备以下能力：

```text
启动游戏
-> 主入口初始化
-> 进入轨道站 / 序章 / 地表远征 / 回归结算
-> 场景之间能传递远征配置、随机种子、库存变更和结算结果
```

## 2. 系统边界

本阶段要做的是最终系统的基础层，不是临时测试菜单。

纳入范围：

- 项目主入口。
- Godot .NET / C# 项目文件。
- 场景切换流程。
- 输入行为定义。
- 全局运行状态。
- 调试启动入口。
- 第一步正式 UI 框架。
- 日志规范。

不在本阶段展开具体内容：

- 地表资源采集数值。
- 轨道交易价格。
- 单位 AI。
- 战斗结算。
- 程序生成细节。
- 角色成长数值。

这些系统可以在界面和数据流中预留入口，但不在第一步实现具体玩法。

## 3. 场景结构

### 3.1 主入口场景

主入口场景是 `project.godot` 的 `application/run/main_scene` 指向对象。

职责：

- 初始化全局服务。
- 加载或创建运行状态。
- 读取输入配置。
- 根据启动模式进入目标场景。
- 统一处理场景切换。

主入口不承载具体玩法逻辑，不直接处理地表单位、轨道交易、火箭建造等系统。

建议节点职责：

- `GameRoot`：运行时根节点，挂载在主入口场景，负责初始化和持有当前场景容器。
- `SceneRouter`：脚本服务，由 `GameRoot` 调用，统一管理进入轨道站、地表、结算、序章。
- `GameSession`：运行状态对象，可作为 Autoload 或由 `GameRoot` 持有，保存轨道层、远征层和轮次记录。
- `DebugLauncher`：独立调试脚本，只在调试配置启用时读取启动参数，不参与正式流程导航。

### 3.2 轨道站场景

轨道站是永久成长层，也是普通流程的主要起点。

第一步需要提供最终结构的 UI 框架：

- 库存页入口。
- 交易页入口。
- 研发页入口。
- 角色页入口。
- 空投配置页入口。
- 页面切换接口：`open_page(page_id)`。
- 页面切换事件：切换页签时发出当前 `page_id`，供后续交易、研发、角色等页面接入。

本阶段页面必须使用最终信息架构和当步实际资源呈现。尚未进入开发步骤的业务内容以正式空状态、锁定状态或无数据状态表达，不用占位数据伪装功能。

### 3.3 地表远征场景

地表远征场景是未来 RTS 玩法承载层。

第一步需要提供场景结构：

- 地图层。
- 单位层。
- 建筑层。
- 投射物 / 效果层。
- 地表 UI 层。
- 调试覆盖层。

地表场景进入时必须接收：

- 远征 ID。
- 随机种子。
- 空投坐标。
- 初始单位列表。
- 初始携带物资。

初始单位和物资只允许使用稳定 ID，不使用显示名传递：

```text
初始单位：{ unit_id, count, config_id }
初始物资：{ item_id, count }
```

`unit_id` 后续对应 `UnitData`，`item_id` 后续对应 `ItemData`，`config_id` 用于表达装备、改装或角色实例配置。

### 3.4 回归结算场景

回归结算场景负责把地表远征结果写回轨道永久层。

第一步需要定义结算数据入口：

- 火箭货舱物资。
- 带回觉醒者。
- 带回芯片和蓝图。
- 损失单位和装备。
- 遗留地表资产。

本阶段使用可保留的首批正式流程数据验证流程，数据必须符合后续结构，不使用一次性假数据。

### 3.5 序章场景

序章用于承接主角动机和“碎石”加入流程。

第一步只需要建立序章流程入口和切换出口：

- 从主入口进入序章。
- 序章结束后进入轨道站或地表远征。
- 序章可传递初始角色和初始远征状态。

## 4. 场景流程

### 4.1 标准流程

```text
启动游戏
-> 主入口
-> 轨道站
-> 空投配置
-> 创建远征
-> 地表远征
-> 火箭回归
-> 回归结算
-> 写入轨道永久数据
-> 返回轨道站
```

### 4.2 序章流程

```text
启动游戏
-> 主入口
-> 序章
-> 空投到目标区域
-> 发现碎石
-> 返回临时基地
-> 进入正式轨道 / 地表循环
```

### 4.3 调试流程

```text
启动游戏
-> 主入口
-> 读取调试配置
-> 直接进入指定场景
```

调试目标包括：

- 直接进入轨道站指定页面。
- 直接进入指定种子的地表远征。
- 直接打开回归结算。
- 直接进入序章指定节点。

调试入口隔离规则：

- 调试跳转只允许由 `DebugLauncher`、启动参数或独立调试配置触发。
- 正式 UI 不默认暴露直接跳转到地表、结算或序章节点的按钮。
- 调试配置必须能被关闭，关闭后启动流程只走正式入口。
- 调试日志统一使用 `[调试]` 前缀，便于和正式流程区分。

## 5. 输入系统

输入行为必须统一配置到 Godot Input Map，后续脚本只引用行为名，不直接写死键位。

### 5.1 鼠标输入

- `select_primary`：鼠标左键，选择单位、点击 UI。
- `command_context`：鼠标右键，下达上下文指令。
- `drag_select`：鼠标左键按住拖拽，框选单位。
- `camera_pan_mouse`：鼠标中键拖拽或屏幕边缘，移动镜头。

### 5.2 键盘输入

- `group_1` 到 `group_9`：数字键 `1` 到 `9`，选择小队。
- `assign_group`：`Ctrl + 数字键`，创建或覆盖小队。
- `open_build_menu`：`B`，打开建造菜单。
- `open_inventory`：`I`，打开库存。
- `open_map`：`M`，打开地图。
- `open_character_panel`：`C`，打开角色面板。
- `toggle_behavior_panel`：`V`，打开行为模式面板。
- `cancel_action`：`Esc` 或鼠标右键，取消当前命令或关闭弹窗。
- `confirm_action`：`Enter`，确认当前选择。

### 5.3 镜头输入

- `camera_move_up`：`W` 或方向键上。
- `camera_move_down`：`S` 或方向键下。
- `camera_move_left`：`A` 或方向键左。
- `camera_move_right`：`D` 或方向键右。
- `camera_zoom_in`：鼠标滚轮上。
- `camera_zoom_out`：鼠标滚轮下。

### 5.4 输入优先级

输入处理优先级：

1. 弹窗和确认框。
2. UI 面板。
3. 地表选择和指令。
4. 镜头控制。
5. 调试快捷键。

这样可以避免玩家点击 UI 时同时给地表单位下达错误指令。

实现责任：

- 统一输入控制器先判断 UI 是否消耗输入。
- UI 已消费的输入不再传递给地表指令层。
- 地表场景只处理未被 UI 消耗的选择、移动、框选和上下文指令。
- 各玩法脚本只接收输入意图，不直接判断物理按键。

## 6. 全局运行状态

第一步需要定义游戏运行状态的顶层结构，供后续系统扩展。

建议状态：

- `boot`：启动中。
- `main_menu`：主入口或开始界面。
- `prologue`：序章。
- `orbit_station`：轨道站。
- `expedition_loading`：远征创建与加载。
- `surface_expedition`：地表远征。
- `return_summary`：回归结算。

核心数据对象：

- `GameSession`：当前游戏会话。
- `OrbitState`：轨道永久层。
- `ExpeditionState`：当前远征层。
- `RunRecord`：已完成轮次记录。
- `ScenePayload`：场景切换携带数据。

### 6.1 状态字段边界

`GameSession`：

- `session_id`：当前会话 ID。
- `current_state`：当前运行状态。
- `orbit_state`：轨道永久层引用。
- `active_expedition`：当前远征层引用，可为空。
- `run_records`：已完成轮次记录列表。

`OrbitState`：

- `inventory`：轨道永久库存。
- `credits`：信用点。
- `unlocked_blueprints`：已解锁蓝图 ID 列表。
- `unlocked_protocols`：已解锁协议 ID 列表。
- `awakened_units`：觉醒者实例 ID 列表。
- `story_flags`：剧情进度和关键标记。

`ExpeditionState`：

- `expedition_id`：远征 ID。
- `seed`：随机种子。
- `drop_position`：空投坐标。
- `initial_units`：初始单位列表，结构为 `{ unit_id, count, config_id }`。
- `initial_items`：初始物资列表，结构为 `{ item_id, count }`。
- `surface_inventory`：地表临时库存引用。
- `map_state`：地图状态接口，包括已探索区域、遗留资产和事件状态。
- `rocket_state`：火箭建造、货舱和回归状态。

`ScenePayload`：

- `from_scene`：来源场景 ID。
- `target_scene`：目标场景 ID。
- `payload_type`：载荷类型。
- `navigation_data`：普通导航载荷。
- `expedition_start_data`：远征创建载荷。
- `return_summary_data`：回归结算载荷。
- `debug_enabled`：是否来自调试入口。
- `seed`：需要复现时携带的种子。

`RunRecord`：

- `expedition_id`：远征 ID。
- `seed`：随机种子。
- `brought_items`：带入物资。
- `returned_items`：带回物资。
- `lost_units`：损失单位。
- `discovered_ids`：发现的蓝图、芯片、觉醒者或坐标。

## 7. 第一步正式 UI 框架

### 7.1 主入口 UI

主入口 UI 提供：

- 开始序章。
- 进入轨道站。
- 继续当前存档。
- 退出游戏。

调试入口不作为正式主入口默认按钮。开发构建可以通过独立调试配置显示调试入口，发布流程默认隐藏。

### 7.2 轨道站 UI 框架

轨道站 UI 提供最终页面导航：

- 库存。
- 交易。
- 研发。
- 角色。
- 空投。

第一步交付正式页签导航、页面切换、页面标题、正式空状态、锁定状态、分类图标和列表视觉规范。物品格、拖拽、筛选、交易确认等业务交互在轨道站步骤展开，但第一步的 UI 资源和信息架构必须可保留。

### 7.3 地表 UI 框架

地表 UI 提供最终布局区域：

- 顶部资源栏。
- 左下小地图区域。
- 底部单位 / 建筑信息面板。
- 右下命令按钮区域。
- 右侧消息和事件提示区域。

布局参考《魔兽争霸》的清晰操作区。

第一步交付正式地表 HUD 布局、顶部资源栏视觉、左下小地图框架、底部信息面板、右下命令区图标风格和右侧消息区视觉。单位详情、技能按钮、资源动态刷新和小地图内容在对应玩法步骤接入，但第一步的 UI 资源和布局不是临时方案。

### 7.4 回归结算 UI 框架

结算 UI 提供：

- 带回物资列表。
- 损失列表。
- 发现内容列表。
- 写入轨道库存确认。
- 返回轨道站按钮。

第一步交付正式结算页面结构、列表视觉、物品图标样式、损失图标样式、发现内容图标样式、确认按钮资源和返回轨道站流程。详细损失计算在火箭回归步骤接入，但结算 UI 的资源规范和空状态必须按最终界面保留。

日志前缀：

- `[启动]`
- `[场景]`
- `[输入]`
- `[轨道]`
- `[远征]`
- `[结算]`
- `[调试]`

关键日志：

- 主入口初始化完成。
- 场景切换开始和完成。
- 输入配置加载完成。
- 创建远征 ID。
- 使用随机种子。
- 进入地表远征。
- 回归结算写入轨道库存。

调试配置建议：

- 调试目标场景。
- 调试远征种子。
- 调试轨道页面。
- 调试序章节点。
- 是否跳过过场。

本机启动脚本：

- `tools/run_godot.ps1`：设置 `DOTNET_ROOT` 和 `PATH` 后启动 Godot 编辑器。
- `tools/run_godot_console.ps1`：设置 `DOTNET_ROOT` 和 `PATH` 后启动 Godot 控制台版，用于 headless 验证。
- 脚本固定使用 Godot .NET 完整路径，避免系统 PATH 中没有 `godot` 或 Godot 找不到 MSBuild。

命名规则：

- 场景文件使用 `snake_case.tscn`。
- 第一批资源图片必须表达真实用途，例如轨道站背景、地表背景、按钮状态、页签图标和基础场景标识，不能只用纯色块或缺失图标代替。
- 缺失图标和缺失贴图只能作为异常兜底资源保留，用于发现未绑定资源的问题，不能作为阶段交付资源。
- 注释使用中文，只写必要解释。
- 不写入本机绝对路径。

## 10. 与后续系统的接口

第一步必须为后续系统留下明确接口。

给轨道站：

- 读取 `OrbitState`。
- 写入交易、研发、空投配置结果。

给地表：

- 接收 `ExpeditionState`。
- 接收随机种子。
- 接收空投单位和携带物资。

给结算：

- 接收地表回归结果。
- 写入轨道永久库存。
- 记录轮次结果。

给序章：

- 创建主角初始状态。
- 创建碎石加入状态。
- 创建序章后的初始轨道或远征状态。

## 11. 验收标准

第一步完成时，应满足：

- Godot 4.6 能打开项目。
- `dotnet build` 能通过 C# 编译。
- `tools/run_godot_console.ps1 --headless --quit` 能加载项目。
- `project.godot` 的主入口指向有效 `.tscn`。
- 游戏启动后进入主入口。
- 主入口可进入轨道站、地表远征、回归结算和序章。
- 轨道站、地表、结算、序章都能返回或切换到下一流程。
- Input Map 中存在所有基础输入行为。
- 基础输入行为实际写入 `project.godot`。
- UI 输入和地表输入有优先级区分。
- 场景切换可以携带结构化数据。
- `ScenePayload`、`OrbitState`、`ExpeditionState`、`GameSession` 字段边界已按本文定义。
- 日志能显示启动、场景切换、远征种子和结算写入。
- 所有新增脚本无语法错误。
- 所有新增场景引用的脚本路径有效。
- 调试入口关闭时，正式流程不会显示直接跳场景功能。
- 主入口、轨道站、地表、结算、序章场景都有可见的基础 UI 和对应实际资源图片。
- 第一批基础按钮图标、页签图标、场景背景图、默认字体配置和基础 UI 皮肤资源已落地到 `assets/`。
- 缺失图标和缺失贴图只作为异常兜底存在，不用于满足阶段资源验收。
- 不包含具体玩法数值的临时代码。
- 不写入本机绝对路径。

## 12. 风险点

需要优先避免的问题：

- 主入口承担过多玩法逻辑，后续难以维护。
- 输入行为在多个脚本中硬编码，后续改键困难。
- 轨道站和地表各自定义库存结构，后续结算难以打通。
- 调试入口和正式入口混杂，导致正式流程不稳定。
- 场景切换只传字符串或散字段，后续扩展容易失控。

处理原则：

- 主入口只做初始化和路由。
- 输入只通过行为名调用。
- 场景切换统一走 `ScenePayload`。
- 远征、轨道、结算都读写明确状态对象。
- 调试能力通过独立调试模块接入。
