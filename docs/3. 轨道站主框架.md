# 第三步策划案：轨道站主框架

## 1. 目标定位

第三步要完成轨道站作为永久成长层的主框架。轨道站是每轮远征的起点和终点，负责读取轨道永久状态、展示库存和角色资产、承载交易与研发入口，并把玩家引导到正式空投配置流程。

本阶段完成后，项目应具备以下能力：

```text
启动或回归轨道站
-> 读取 OrbitState
-> 查看永久库存、信用点、蓝图、协议、角色和已知坐标
-> 切换库存 / 交易 / 研发 / 角色 / 空投页面
-> 执行首批正式交易和研发解锁
-> 为后续空投配置创建明确入口
```

本阶段不是完整轨道经济平衡阶段，也不是空投配置实现阶段。交易、研发、角色和空投页面必须按最终结构落地可保留的界面、数据读取方式和资源引用；未展开的复杂交互以正式锁定、不可用原因或空状态表达，不用假数据或临时按钮伪装后续功能。

## 2. 系统边界

纳入范围：

- 轨道站主 UI 框架。
- 轨道站页面导航和页面状态。
- `OrbitState` 读取和展示。
- 轨道永久库存查看。
- 首批正式交易条目。
- 首批正式研发解锁条目。
- 觉醒者和量产单位资产概览。
- 已知坐标和空投入口概览。
- 轨道站相关 UI 资源、图标、背景、音效反馈。
- 轨道站页面的输入隔离和确认反馈。

不在本阶段完整展开：

- 空投舱装载、容量计算和远征创建。
- 地表单位 RTS 控制。
- 地表矿产、物品物流、建造、生产和电力系统。
- 火箭装载和回归结算计算。
- 完整交易价格平衡。
- 完整研发树或角色改装树。

这些内容必须在界面和数据接口中保留最终入口，但不在第三步使用临时逻辑提前实现。

## 3. 开发依赖顺序

本阶段按以下顺序开发，避免先做页面表现而缺少状态来源。

1. 明确轨道站读取的 `OrbitState`、库存、角色、蓝图、协议和坐标字段。
2. 明确轨道站主布局、信息密度基准、页签区、列表区、详情区和操作区。
3. 建立轨道站页面导航、页面 ID、当前页状态和输入隔离。
4. 落地页签、分类、面板、按钮状态、状态图标和反馈音效等首批正式资源。
5. 完成库存页的永久库存读取、分类、空状态和条目详情，并实际引用道具。
6. 完成交易页的首批正式交易条目、可购买条件、确认流程和审计记录。
7. 完成研发页的首批正式解锁条目、消耗检查、解锁写回和审计记录。
8. 完成角色页的觉醒者、量产单位和角色资产概览。
9. 完成空投页的准备入口、已知坐标概览和后续空投配置接口。
10. 验证从结算写回后的轨道库存和解锁状态能被轨道站读取显示。

## 4. 轨道站状态入口

轨道站只读取和修改轨道永久层，不直接创建地表远征，不伪造回归结算。

### 4.1 读取数据

轨道站启动时读取：

- `OrbitState.inventory_id`：轨道永久库存。
- `OrbitState.credits`：信用点。
- `OrbitState.unlocked_blueprint_ids`：已解锁蓝图。
- `OrbitState.unlocked_protocol_ids`：已解锁协议。
- `OrbitState.awakened_unit_instance_ids`：觉醒者列表。
- `OrbitState.available_mass_unit_instance_ids`：轨道停放的量产单位实例。
- `OrbitState.known_coordinates`：已知空投坐标。
- `OrbitState.completed_run_record_ids`：已完成轮次记录。
- `OrbitState.story_flags`：剧情和功能开放状态。

轨道站不得直接读取地表临时库存作为永久资产。回归收益必须先通过回归结算链路写入 `OrbitState`，再由轨道站展示。

### 4.2 写入数据

本阶段允许轨道站写入：

- 交易消耗和获得的轨道库存道具。
- 交易消耗和获得的信用点。
- 研发解锁的蓝图 ID。
- 研发解锁的协议 ID。
- 交易或研发产生的轮次外审计记录 `OrbitTransactionRecord`。

本阶段不允许轨道站写入：

- 当前地表地图状态。
- 地表仓库库存。
- 火箭货舱库存。
- 回归结算结果。
- 未经空投配置生成的 `ExpeditionState`。

## 5. 页面导航和输入规则

### 5.1 页面 ID

轨道站页面使用稳定 ID：

- `inventory`：库存。
- `trade`：交易。
- `research`：研发。
- `characters`：角色。
- `drop`：空投。

页面切换只改变轨道站当前页状态，不改变游戏会话的大状态。轨道站仍属于 `orbit_station` 运行状态。

### 5.2 导航规则

轨道站顶部或左侧提供固定页签导航：

- 当前页签高亮。
- 不可用页签显示锁定状态和原因。
- 页面切换保留同一轨道站背景和主布局。
- 页面内部的选择项可以重置，但轨道站全局状态不重建。

页面切换日志使用 `[轨道]` 前缀，记录来源页和目标页。

### 5.3 输入隔离

轨道站 UI 必须消费自身点击、滚动、确认和取消输入，不把输入传递到地表 RTS 控制层。

优先级：

1. 确认弹窗和交易 / 研发二次确认。
2. 页面内列表、筛选和详情面板。
3. 页签导航。
4. 全局返回或关闭输入。

`Esc` 规则：

- 有确认弹窗时关闭弹窗。
- 有详情面板时关闭详情或清除选择。
- 无二级界面时不退出正式流程，除非后续主菜单流程明确接管。

## 6. 轨道站主布局基准

轨道站 UI 参考《远行星号》的信息密度和功能性，首屏直接服务轨道准备流程，不做营销式首页，不使用大面积空白装饰或只展示背景图的入口页。

### 6.1 全局布局

轨道站主界面采用固定功能布局：

- 顶部状态栏：显示信用点、当前轨道状态、关键提醒和最近一次远征摘要入口。
- 左侧页签区：库存、交易、研发、角色、空投五个固定页签。
- 中央列表区：显示当前页面的主要对象列表。
- 右侧详情区：显示选中对象的描述、消耗、收益、限制、状态和资源引用。
- 底部操作区：显示确认、取消、筛选、排序、锁定原因和失败提示。

页面切换保留同一布局骨架，只替换中央列表和右侧详情内容。

库存页、交易消耗预览、研发消耗预览和空投候选摘要必须复用 `docs/统一库存容器UI设计方案.md` 的道具格、容器头、状态角标和道具详情规则。轨道站库存可以使用高密度列表视图，但不能形成一套只属于轨道站的独立库存 UI。

### 6.2 列表信息密度

库存列表至少显示：

- 图标。
- 名称。
- 分类。
- 数量。
- 单个重量。
- 总重量。
- 基础价值。

交易和研发列表至少显示：

- 图标。
- 名称。
- 分类。
- 主要消耗。
- 主要收益或解锁内容。
- 当前状态：可执行、物资不足、前置未满足、已完成、锁定。

角色列表至少显示：

- 头像。
- 名称。
- 类型。
- 状态。
- 核心技能摘要。
- 当前可参与空投状态。

### 6.3 详情和确认区

详情区必须显示完整消耗、获得、前置条件和失败原因。交易和研发确认不能只依赖按钮文字，必须在确认前展示消耗后库存变化或解锁结果预览。

确认区按钮使用明确状态：

- 可执行。
- 物资不足禁用。
- 前置不足禁用。
- 已完成禁用。
- 模块未接入锁定。

## 7. 库存页

### 7.1 页面目标

库存页用于查看轨道永久资产，让玩家理解下一次远征可支配的矿产道具、加工产物、装备、芯片、工具和单位平台。

### 7.2 显示内容

库存页读取 `OrbitState.inventory_id` 指向的库存容器，显示：

- 基础矿产。
- 加工产物。
- 关键数据和数据核心。
- AI 芯片。
- 改装件。
- 武器。
- 工具。
- 单位平台。
- 建筑模块。
- 蓝图和蓝图碎片。
- 消耗品。

库存页显示为统一库存容器的轨道高密度变体：

- 容器头显示“轨道永久库存”、容量、重量、筛选状态和只读 / 可操作状态。
- 道具列表行复用统一道具格的图标、分类色条、状态角标和数量规则。
- 详情区复用统一道具详情，必须显示当前位置为 `orbit_inventory`。

每个条目显示：

- 图标。
- 名称。
- 数量。
- 分类。
- 单个重量。
- 总重量。
- 基础价值。
- 标签摘要。

选中条目后显示详情：

- 描述。
- 可用于哪些系统。
- 是否可交易。
- 是否可研发消耗。
- 是否可空投携带。
- 资源引用缺失警告。

### 7.3 分类和筛选

首批分类：

- 全部。
- 矿产 / 物资。
- 装备。
- 芯片。
- 单位平台。
- 蓝图。
- 关键物。

筛选只改变显示，不改变库存顺序和存档内容。

### 7.4 空状态

库存为空时显示正式空状态：

- 当前轨道库存无可显示物资。
- 提示需要通过远征回归、交易或研发获得物资。

不得用假物品填充列表。

## 8. 交易页

### 8.1 页面目标

交易页用于把轨道库存道具和信用点转换为新的远征选项。交易不是线性升级树，而是提供装备、芯片、工具、单位平台和蓝图等选择。

### 8.2 交易数据

交易条目建议使用 `TradeOfferData` 或等价 `Resource` 定义。

字段建议：

- `id`：稳定交易 ID。
- `display_name`：显示名。
- `description`：描述。
- `cost_items`：消耗道具。
- `cost_credits`：消耗信用点。
- `reward_items`：获得道具。
- `reward_item_instances`：获得实例道具定义，可为空。
- `required_blueprint_ids`：需要已解锁蓝图。
- `required_protocol_ids`：需要已解锁协议。
- `required_story_flags`：需要剧情标记。
- `stock_limit`：库存限制，可为空。
- `icon_path`：交易图标。

### 8.4 交易流程

交易流程：

```text
选择交易条目
-> 检查库存和信用点
-> 显示消耗与获得预览
-> 玩家确认
-> 扣除消耗
-> 写入获得物
-> 生成 OrbitTransactionRecord
-> 刷新库存页和交易页状态
```

交易失败必须返回明确原因：

- 信用点不足。
- 道具不足。
- 交易已售罄。
- 前置蓝图未解锁。
- 前置协议未解锁。
- 剧情条件不满足。
- 数据定义缺失。

交易成功日志使用 `[轨道]` 或 `[库存]` 前缀。

## 9. 研发页

### 9.1 页面目标

研发页用于把矿产道具、加工产物、纯净数据、蓝图碎片和数据核心转化为新的可用选项。研发结果影响后续地表建筑、装备、协议、空投能力和扫描能力。

### 9.2 研发数据

研发条目建议使用 `ResearchProjectData` 或等价 `Resource` 定义。

字段建议：

- `id`：稳定研发 ID。
- `display_name`：显示名。
- `description`：描述。
- `category`：研发分类。
- `cost_items`：消耗道具。
- `cost_credits`：消耗信用点。
- `required_research_ids`：前置研发。
- `required_story_flags`：剧情条件。
- `unlock_blueprint_ids`：解锁蓝图。
- `unlock_protocol_ids`：解锁协议。
- `icon_path`：研发图标。

空投舱能力改进统一表达为蓝图或协议解锁，不在本阶段新增 `OrbitState.unlocked_drop_pod_ids` 字段。第四步空投配置读取蓝图和协议后决定可用空投舱类型与容量。

### 9.4 研发流程

研发流程：

```text
选择研发条目
-> 检查前置和消耗
-> 显示解锁内容
-> 玩家确认
-> 扣除消耗
-> 写入蓝图 / 协议解锁
-> 生成 OrbitTransactionRecord
-> 刷新研发页和相关页面
```

已完成研发显示完成状态，不允许重复消耗，除非条目显式支持多次购买。

## 10. 轨道交易审计记录

交易和研发会改变轨道库存、信用点、蓝图和协议状态，必须持久化为轮次外审计记录，不能只写运行日志。

### 10.1 OrbitTransactionRecord

`OrbitTransactionRecord` 字段建议：

- `transaction_id`：交易记录 ID。
- `transaction_type`：`trade` 或 `research`。
- `source_id`：交易条目 ID 或研发条目 ID。
- `cost_items`：消耗道具列表。
- `cost_credits`：消耗信用点。
- `credits_before`：执行前信用点。
- `credits_after`：执行后信用点。
- `reward_items`：获得道具列表。
- `reward_item_instance_ids`：获得实例道具 ID，可为空。
- `unlock_blueprint_ids`：解锁蓝图 ID，可为空。
- `unlock_protocol_ids`：解锁协议 ID，可为空。
- `created_at`：创建时间或会话内时间戳。
- `related_transfer_ids`：关联库存转移记录 ID。
- `result`：成功、失败或已回滚。
- `failure_reason`：失败原因，可为空。

### 10.2 持久化规则

`SaveGame` 顶层增加或预留 `orbit_transaction_records`，保存交易和研发产生的审计记录。`OrbitState` 可保存最近交易记录 ID 或只通过存档顶层查询；不得把审计记录混入 `RunRecord`，因为交易和研发不属于地表轮次结算。

成功交易和研发必须记录：

- 扣除前后的信用点变化。
- 关联库存转移记录。
- 解锁前后的蓝图或协议变化。

失败交易和研发至少记录运行日志；如果失败发生在部分写入之后，必须记录审计并回滚或标记失败，避免读档后无法解释状态。

## 11. 角色页

### 11.1 页面目标

角色页用于展示轨道层可用觉醒者和量产单位资产，强调觉醒者长期培养价值和量产机消耗品属性的区别。

### 11.2 觉醒者列表

读取 `OrbitState.awakened_unit_instance_ids`，显示：

- 头像。
- 名称。
- 单位类型。
- 当前耐久和能源。
- 技能等级：工程、射击、挖矿、控制。
- 装备摘要。
- 改装摘要。
- 当前状态：待命、锁定、远征中、受损、剧情不可用。

首批正式角色：

- `dexter`：主角“灵巧”。
- `rockbreaker`：矿工觉醒者“碎石”。

如果角色尚未加入，角色页可以显示线索或锁定卡片，但必须清楚标注来源条件，不伪造可用角色。

### 11.3 量产单位资产

读取：

- `OrbitState.available_mass_unit_instance_ids`：已实例化并停放在轨道的量产单位。
- 轨道库存中 `unit_platform` 类道具：尚未实例化的平台和机体。

显示：

- 服务型量产机器人数量。
- 轻型运输无人机数量。
- 重型运输机器人数量。
- 当前可空投数量。
- 受损或不可用原因。

### 11.4 本阶段不做内容

角色页本阶段不做：

- 完整装备拖拽。
- 改装树编辑。
- 熟练度升级细节。
- 角色剧情对话。

这些入口可以显示为锁定或后续系统入口，但不能写入临时角色成长逻辑。

## 12. 空投页入口

### 12.1 页面目标

空投页在第三步只作为后续“空投配置与远征创建”的正式入口，展示已知坐标、可用空投舱概览和准备状态，不创建正式远征。

### 12.2 显示内容

空投页显示：

- 已知坐标列表。
- 当前可用空投舱类型。
- 可用觉醒者数量。
- 可用量产机平台数量。
- 可携带物资和装备概览。
- 进入空投配置流程的按钮。

### 12.3 接口边界

点击进入空投配置时：

- 只导航到后续空投配置场景或页面入口。
- 不扣除轨道库存。
- 不创建 `DropPlan`。
- 不创建 `ExpeditionState`。
- 不跳转地表。

如果第四步尚未实现，按钮显示正式锁定状态和原因：`空投配置模块尚未接入`。

## 15. 与后续系统的接口

### 15.1 给空投配置与远征创建

轨道站空投页提供：

- 当前轨道库存引用。
- 可用觉醒者 ID。
- 可用量产单位实例 ID。
- 可用单位平台道具。
- 已知坐标。
- 已解锁蓝图 ID。
- 已解锁协议 ID。

第四步负责：

- 创建 `DropPlan`。
- 检查空投舱容量和重量。
- 锁定或扣除携带物资。
- 创建正式 `ExpeditionState`。
- 根据蓝图和协议决定可用空投舱类型与容量，不要求第三步新增独立空投舱解锁字段。

### 15.2 给回归结算

回归结算完成后写入：

- 轨道库存。
- 觉醒者状态。
- 蓝图、协议、坐标。
- 轮次记录。

轨道站只负责刷新并显示这些状态。主入口和轨道站不得为正式流程伪造回归收益。

### 15.3 给地表系统

轨道站通过研发和交易影响后续地表可用选项：

- 解锁建筑蓝图。
- 解锁工具和武器来源。
- 解锁协议。
- 增加空投携带物资。

地表系统后续只读取已解锁状态和空投结果，不反向依赖轨道站 UI。

## 16. 验收标准

第三步完成时，应满足：

- 轨道站能从正式启动流程进入。
- 轨道站能读取 `OrbitState` 并展示信用点、库存、蓝图、协议、角色和坐标。
- 库存页能按统一道具体系展示轨道永久库存。
- 库存页复用统一库存容器组件语言，轨道高密度列表不与单位背包、建筑库存和货舱形成互不兼容的样式。
- 库存页空状态不使用假物品。
- 库存条目能显示图标、数量、分类、重量、价值和详情。
- 交易页能展示首批正式交易条目。
- 首批正式交易条目包含可写入 Resource 的消耗道具、消耗信用点、获得道具、前置条件和图标资源引用。
- 交易页能检查信用点、道具、前置条件和库存限制。
- 交易成功能扣除消耗并写入获得物。
- 交易失败能显示明确原因并写日志。
- 交易成功能生成 `OrbitTransactionRecord`，并关联库存转移记录。
- 研发页能展示首批正式研发条目。
- 首批正式研发条目包含可写入 Resource 的消耗道具、消耗信用点、解锁蓝图、解锁协议、前置条件和图标资源引用。
- 研发成功能扣除消耗并写入蓝图或协议解锁。
- 研发成功能生成 `OrbitTransactionRecord`，并关联库存转移记录。
- 已完成研发不会重复消耗。
- 空投舱容量改进通过蓝图或协议表达，不新增与第二步 `OrbitState` 不一致的独立空投舱解锁字段。
- 角色页能区分觉醒者、量产单位实例和单位平台道具。
- 角色页能展示“灵巧”和“碎石”的可用或锁定状态。
- 空投页只提供后续空投配置入口，不直接创建远征。
- 轨道站 UI 输入不会穿透到地表输入。
- 轨道站布局具备页签区、状态栏、列表区、详情区和操作区，库存、交易、研发列表达到本文信息密度要求。
- 页签切换、列表选择、确认和失败都有实际反馈。
- 轨道站所需图标、面板、按钮状态、背景和音频资源已落地并被实际引用。
- 首批交易和研发图标不是缺失图标、纯色块或通用占位资源。
- 从回归结算写入轨道库存后，轨道站库存页能读取并显示新增物资。
- `dotnet build` 通过。
- 有 `.sln` 时 `dotnet build godotgame1.sln` 通过。
- Godot headless 能加载项目并实例化轨道站场景。
- 不引入地表玩法、火箭结算或空投创建的临时实现。
- 不写入本机绝对路径。

## 17. 风险点

需要优先避免的问题：

- 轨道站 UI 自己维护一份库存副本，导致结算写入后显示不同步。
- 交易和研发绕过统一库存操作，产生道具扣除不可追踪的问题。
- 空投页提前创建远征，污染第四步的职责边界。
- 把未实现系统用假数据填满页面，后续难以区分真实状态和演示内容。
- 轨道站直接读取地表临时状态，破坏永久层和轮次层边界。
- 只验证按钮可点击，不验证交易、研发和结算写回后的读取链路。
- 资源文件存在但没有被界面实际引用，导致资源落地验收失真。

处理原则：

- 轨道站只以 `OrbitState` 和统一库存为权威数据源。
- 交易和研发统一走库存操作和明确写回结果。
- 空投页只做入口，正式远征创建留给第四步。
- 页面未解锁内容使用正式锁定和空状态，不使用临时假数据。
- 每个 UI 资源和音频反馈都要被实际节点或主题引用。
