# 遗留问题

本文只记录后续需要解决的遗留问题。流程经验和已写入入口规则的工作方法不列入本文。

## 1. ScenePayload 通用字典保留

- 当前状态：`ScenePayload` 已拆分为导航载荷、远征创建载荷、回归结算载荷，但仍保留 `Data` 通用字典。
- 为什么现在不解决：第一步刚完成 payload 语义拆分，当前代码已经不再依赖 `Data` 传业务字段；立即删除会扩大改动面，需要同步确认所有场景、调试参数和 Godot 序列化路径都没有残留引用。
- 影响：如果后续继续往 `Data` 写业务散字段，会重新削弱 payload 语义边界，导致场景之间隐式耦合。
- 什么时候解决：新增第二个以上真实场景 payload 数据类后，或搜索确认 `Data` 连续一个开发步骤没有被使用时解决。
- 后续处理：新增场景流程时优先创建明确 payload 数据类；确认 `Data` 长期无用途后删除，或仅保留给调试元数据。
- 阻断级别：当前不阻断第一步；后续继续扩展场景 payload 前必须解决。

## 2. 远征创建职责仍在 GameRoot

- 当前状态：首批正式远征状态由 `GameRoot.CreateExpeditionStartPayload()` 创建。
- 为什么现在不解决：第一步目标是运行骨架和流程闭环，尚未开发正式空投配置、轨道库存扣除、角色选择和远征规则；现在拆服务会提前设计未确定的边界。
- 影响：第一步作为流程骨架可接受，但后续空投配置、轨道库存扣除、角色选择接入后，主入口会承担过多玩法职责。
- 什么时候解决：开发“轨道空投配置”或任何会修改初始单位、携带物资、空投坐标、库存扣除的功能时解决。
- 后续处理：开发正式空投配置时，将远征创建迁移到轨道空投模块或独立远征创建服务，`GameRoot` 只负责路由。
- 阻断级别：当前不阻断第一步；开发轨道空投配置时必须解决。

## 3. 字体配置未形成完整加载链路

- 当前状态：`assets/ui/fonts/default_ui_font_config.tres` 已落地，运行时基础主题由 `UiAssets.CreateBaseTheme()` 创建并使用按钮、面板资源。
- 为什么现在不解决：当前阶段还没有确定正式字体资产，强行绑定字体文件会变成临时资源；现有主题已能统一字号和基础皮肤，满足第一步基础 UI 验收。
- 影响：当前使用 Godot 默认字体和主题字号，可以满足第一步基础 UI；后续接入正式字体时仍需补强加载链路。
- 什么时候解决：确定正式字体资源，或开始做轨道站/地表 HUD 的正式视觉统一阶段时解决。
- 后续处理：引入正式字体资源时，建立 `Theme` 或字体资源加载入口，并确认所有主场景继承同一 UI 主题。
- 阻断级别：当前不阻断第一步；接入正式字体或做 UI 统一时必须解决。

## 4. UI 输入隔离需要随新面板扩展

- 当前状态：地表 HUD 的顶部栏、小地图、信息面板、命令区和消息区已注册输入阻塞。
- 为什么现在不解决：第一步只交付基础 HUD 区域，弹窗、建造菜单、库存拖拽等交互还没有真实节点；无法为不存在的面板做最终输入优先级验证。
- 影响：后续新增弹窗、拖拽面板、建造菜单或库存面板时，如果没有接入统一阻塞逻辑，仍可能发生点击 UI 同时触发地表指令。
- 什么时候解决：每次新增可点击、可拖拽、会覆盖地表画面的 UI 面板时同步解决；新增弹窗时必须优先处理。
- 后续处理：新增 UI 面板时统一调用输入阻塞注册逻辑，复杂弹窗应优先于普通 UI 面板消费输入。
- 阻断级别：当前不阻断第一步；新增复杂 UI 面板或弹窗时必须解决。

## 5. 资源导入与运行时加载策略需统一

- 当前状态：首批 SVG 资源通过运行时 SVG 解析加载，避免 headless 未导入资源时加载失败。
- 为什么现在不解决：第一步资源数量少，运行时 SVG 解析能保证命令行和 headless 验证稳定；现在制定完整导入规范会依赖后续美术资源格式和导出策略。
- 影响：后续若混用导入纹理、运行时 SVG、位图资源，可能出现编辑器能显示但 headless 或导出包加载路径不一致。
- 什么时候解决：开始批量引入位图、字体、音频或准备第一次导出包前解决。
- 后续处理：美术资源规模扩大后，制定统一导入规则；验证时同时覆盖编辑器、headless 和导出前资源路径。
- 阻断级别：当前不阻断第一步；批量引入资源或准备导出前必须解决。
