# 遗留问题

本文只记录后续需要解决的遗留问题。流程经验、已写入入口规则的工作方法和已解决事项不列入本文。

## 1. 远征创建职责仍在 GameRoot

- 当前状态：首批正式远征状态仍由 `GameRoot.CreateExpeditionStartPayload()` 创建；轨道站第三步只保留空投入口锁定，不创建正式远征。
- 为什么现在不解决：正式空投配置、轨道库存扣除、角色选择、平台转单位和远征规则属于第四步“空投配置与远征创建”。现在拆服务会提前设计尚未落地的配置边界。
- 影响：第四步接入后，如果继续让 `GameRoot` 直接创建空投计划、扣除库存和生成远征状态，主入口会承担过多玩法职责。
- 什么时候解决：开发“轨道空投配置”或任何会修改初始单位、携带物资、空投坐标、库存扣除的功能时解决。
- 后续处理：开发正式空投配置时，将远征创建迁移到轨道空投模块或独立 `ExpeditionCreationService`，`GameRoot` 只负责路由和服务调用。
- 阻断级别：开发第四步空投配置时必须解决。

## 2. 字体配置未形成完整加载链路

- 当前状态：`assets/ui/fonts/default_ui_font_config.tres` 已落地，运行时基础主题由 `UiAssets.CreateBaseTheme()` 创建并使用按钮、面板资源。
- 为什么现在不解决：当前阶段还没有确定正式字体资产，强行绑定字体文件会变成临时资源；现有主题已能统一字号和基础皮肤。
- 影响：当前使用 Godot 默认字体和主题字号，后续接入正式字体时仍需补强加载链路。
- 什么时候解决：确定正式字体资源，或开始做轨道站/地表 HUD 的正式视觉统一阶段时解决。
- 后续处理：引入正式字体资源时，建立 `Theme` 或字体资源加载入口，并确认所有主场景继承同一 UI 主题。
- 阻断级别：接入正式字体或做 UI 统一时必须解决。

## 3. UI 输入隔离需要随新面板扩展

- 当前状态：地表 HUD 的顶部栏、小地图、信息面板、命令区和消息区已注册输入阻塞；轨道站 UI 进入时会阻塞地表输入。
- 为什么现在不解决：弹窗、建造菜单、库存拖拽等复杂交互还没有真实节点；无法为不存在的面板做最终输入优先级验证。
- 影响：后续新增弹窗、拖拽面板、建造菜单或库存面板时，如果没有接入统一阻塞逻辑，仍可能发生点击 UI 同时触发地表指令。
- 什么时候解决：每次新增可点击、可拖拽、会覆盖地表画面的 UI 面板时同步解决；新增弹窗时必须优先处理。
- 后续处理：新增 UI 面板时统一调用输入阻塞注册逻辑，复杂弹窗应优先于普通 UI 面板消费输入。
- 阻断级别：新增复杂 UI 面板或弹窗时必须解决。

## 4. 资源导入与运行时加载策略需统一

- 当前状态：首批 SVG 资源通过运行时 SVG 解析加载；轨道站音频在 headless 下检查文件存在，运行时可直读 WAV 数据，避免未导入资源导致验证失败。
- 为什么现在不解决：当前资源规模仍小，运行时加载策略能保证命令行和 headless 验证稳定；完整导入规范会依赖后续美术资源格式和导出策略。
- 影响：后续若混用导入纹理、运行时 SVG、位图资源、字体和音频，可能出现编辑器能显示但 headless 或导出包加载路径不一致。
- 什么时候解决：开始批量引入位图、字体、音频或准备第一次导出包前解决。
- 后续处理：美术资源规模扩大后，制定统一导入规则；验证时同时覆盖编辑器、headless 和导出前资源路径。
- 阻断级别：批量引入资源或准备导出前必须解决。

## 5. 核心定义数据仍主要由代码注册

- 当前状态：交易和研发首批正式数据已迁移到 `resources/data/trade_offers/` 与 `resources/data/research_projects/` 的 Godot Resource；但 `ItemData`、`UnitData`、`BuildingData`、`RecipeData`、`SkillData`、`EventData`、`DropPodData` 等核心定义仍通过 `DataRegistry` 代码注册。
- 为什么现在不解决：第三步只需要交易和研发条目可配置；把全部核心定义迁移为 `.tres` 或外部数据文件会扩大改动面，并需要同步设计编辑器工作流、导入规范和数据校验入口。
- 影响：核心数据可验证但编辑器可配置性不足。后续扩展大量道具、单位、建筑、配方或事件时，如果继续堆在 `DataRegistry`，会让数据维护、差异审查和美术引用调整变重。
- 什么时候解决：开始批量扩展道具、单位、建筑、配方、事件之前解决；如果策划要求非程序人员直接编辑核心定义数据，也必须提前解决。
- 后续处理：明确核心定义数据资产格式，优先迁移到 `resources/data/` 下的 Godot Resource 或稳定外部数据文件；保留 `DataRegistry` 作为加载、索引、校验和缺失资源报告入口。
- 阻断级别：批量扩展核心正式数据前必须解决。

## 6. GameRoot 仍承担数据初始化和流程服务职责

- 当前状态：轨道交易和研发已拆到 `OrbitTransactionService`；但 `GameRoot` 仍负责加载 `DataRegistry`、初始化轨道库存、创建空投计划、创建远征状态、执行调试回归货舱装载和应用回归结算。
- 为什么现在不解决：本轮只清理已到条件的遗留项；继续拆 `GameRoot` 会牵连第四步空投配置、正式存档、地表火箭装载和回归结算服务边界。
- 影响：`GameRoot` 代码仍会继续膨胀；后续若在其中继续加入空投配置、生产、火箭建造或存档读写，会让主入口承担玩法服务，增加回归风险。
- 什么时候解决：开发正式空投配置 UI、地表火箭装载/回归、存档读写或第二个以上状态写回服务时解决。
- 后续处理：拆出 `SessionBootstrapService`、`ExpeditionCreationService`、`ReturnSettlementService` 和正式存档读写服务；`GameRoot` 只保留初始化、路由和服务调用。
- 阻断级别：第四步空投配置或接入第二个以上状态写回服务时必须解决。

## 7. 正式火箭装载和回归链路尚未实现

- 当前状态：第二步已建立火箭货舱库存 ID、回归 payload、实例道具回归、转移记录和正式结算校验；正式流程会拒绝未建成、未确认发射或缺少有效货舱内容的回归。调试路径可通过 debug 标志生成验证货舱数据。
- 为什么现在不解决：火箭建造、装载 UI、超载燃料消耗和发射反馈属于后续火箭系统步骤，不属于当前遗留清理范围。
- 影响：正式地表流程中玩家还不能通过真实火箭装载完成回归；当前只能验证数据结构和防伪造边界，不能作为火箭玩法验收。
- 什么时候解决：开发“火箭建造、装载、回归和结算”步骤时解决；如果某个前置步骤需要从地表真实带回物资，也必须先接入对应链路。
- 后续处理：实现火箭组装坪状态、货舱装载 UI、可返回单位/实例选择、发射确认和超载反馈；回归 payload 必须只由该链路生成，并复用现有结算校验。
- 阻断级别：实现正式回归玩法前必须解决。

## 8. 存档服务已有校验但尚未落地读写文件

- 当前状态：第二步新增 `SaveGame` 和 `SaveGameService`，能校验版本、库存、实例引用、空投计划、轮次转移记录、轨道交易审计记录、实例所有权和火箭超载标记；但还没有正式保存到磁盘、读档迁移和错误恢复 UI。
- 为什么现在不解决：当前阶段重点是定义存档结构和校验规则，正式读写、迁移和槽位管理会涉及 UI、文件路径、版本升级策略和失败恢复流程。
- 影响：当前会话状态只能运行时存在，不能作为完整存档系统验收；后续读档时仍需补充迁移、兼容和错误展示。
- 什么时候解决：开始做继续游戏、存档槽、读档恢复、死亡/回归后自动保存或版本迁移时解决。
- 后续处理：实现 `SaveGameService` 的序列化、反序列化、版本迁移、备份和恢复报告；读档后必须重新关联 Resource 定义并运行完整校验。
- 阻断级别：正式存档/读档功能前必须解决。

## 9. 新增 C# 脚本 UID 尚未随脚本纳入版本管理

- 当前状态：轨道站拆分和交易研发实现新增了多份 `scripts/orbit/*.cs`，Godot headless 已生成对应 `.cs.uid` 文件；入口规则已明确 `.cs.uid` 应随脚本纳入版本管理，但这些 UID 当前仍以未跟踪文件形式留在工作区。
- 为什么现在不解决：本轮只是经验和遗留文档整理，不执行暂存或提交；直接处理版本状态会扩大任务范围，并可能混入其他未提交变更。
- 影响：如果提交新增 C# 脚本时遗漏对应 `.cs.uid`，可能造成 Godot 对脚本资源识别不稳定，或让后续审查无法确认脚本元数据是否完整。
- 什么时候解决：提交轨道站拆分、交易研发实现或任何新增 C# 脚本前解决。
- 后续处理：提交前用 `git status --short` 核对新增 `.cs` 和 `.cs.uid` 是否成对出现；将对应 `.cs.uid` 与脚本一起纳入版本管理，或在确认脚本已删除时同步删除孤立 UID。
- 阻断级别：提交新增 C# 脚本前必须解决。

## 10. 位置化道具和物流模型仍缺完整玩法系统

- 当前状态：运行时代码已移除旧的泛资源分类和顶部总量条，并新增道具位置、地上道具、物流订单、施工点、建筑输入库存和建筑输出库存的基础状态结构。
- 为什么现在不解决：本轮只清理错误代码、文件和资源，并落地基础状态边界；完整地表采集、自动搬运、施工推进、生产消耗和建筑输出清空仍属于后续玩法实现。
- 影响：如果后续实现只写 UI 或直接改库存数量，仍可能绕过真实位置、物流订单、施工点和建筑输入 / 输出库存。
- 什么时候解决：开发地表矿产采集、物流、建造、生产、火箭装载或对应 UI 交互时解决。
- 后续处理：所有物品移动必须从具体位置到具体位置；采集产物进入地上、单位背包或目标库存；建造先创建施工点并搬入材料；生产只读建筑输入库存，只写建筑输出库存。
- 阻断级别：实现地表采集、物流、建造、生产和火箭装载前必须遵守。
