# 第七步策划案：探索、战争迷雾、扫描和区域内容

## 1. 目标定位

第七步要把第五步建立的地表单位控制、侦察、扫描和小地图入口，以及第六步建立的矿产、建筑、库存和地表对象接口，接入地表远征的主要内容来源。玩家需要通过单位视野、侦察路线、扫描工具和区域标记逐步揭示地图，发现矿产点、废墟、特殊信号、失控设施、拾荒者机器活动区和环境危险区域，并把探索结果写回当前远征状态。

本阶段完成后，项目应具备以下能力：

```text
地表远征
-> 读取 ExpeditionState、SurfaceUnitRuntimeState、MineralDepositInstance 和地表坐标系
-> 创建 SurfaceMapState、RegionState、FogCellState 和 ExplorationContentState
-> 根据单位、建筑和扫描事件计算当前可见区域
-> 保存已探索但当前不可见区域的历史信息
-> 在小地图、地图叠层和地表对象上显示探索状态
-> scout 指令推动单位进入未探索区域
-> scan 指令揭示矿产点、废墟、特殊信号和区域内容
-> 把发现记录、地图标记、扫描记录、探索奖励和隐藏坐标线索写回 ExpeditionState
```

本阶段是地表内容发现层，不是完整战斗、角色成长、火箭回归或完整程序生成阶段。拾荒者机器活动区、失控设施和环境危险区域可以作为可见风险标记和后续系统目标出现，但敌对单位生成、伤害、炮塔攻击、AI 行为和防御协议激活由第八步接管；技能经验、觉醒者成长、芯片安装和角色改装由第九步接管；火箭带回、轨道永久解锁和回归结算由第十步接管；完整程序生成、随机事件权重和复现调试由第十一步接管。

## 2. 系统边界

纳入范围：

- 地表地图状态、区域状态和区域邻接关系。
- 战争迷雾三态：未知、已探索、当前可见。
- 单位、建筑和扫描事件提供的视野揭示。
- 小地图真实探索状态、镜头框和地图标记。
- `scout` 指令的侦察目标、可达性过滤和发现记录。
- `scan` 指令的目标解析、进度、范围、精度、失败原因和结果写回。
- 矿产点从隐藏、已发现、已扫描到可采集的状态衔接。
- 废墟、特殊信号、失控设施、拾荒者机器活动区和环境危险区域的地表实例。
- 蓝图碎片、旧世界芯片、AI 芯片、觉醒个体线索、数据核心线索和隐藏坐标的探索奖励状态。
- 本阶段需要的战争迷雾视觉、扫描效果、区域标记、废墟外观、特殊信号、地图图标和音效资源。

不在本阶段完整展开：

- 敌对单位实例、敌意传播、武器伤害、受击、死亡、掉落和防御建筑攻击。
- 熟练度经验、角色成长、觉醒者剧情加入、AI 芯片安装和改装树效果。
- 火箭建造、火箭货舱装载、发射、回归结算和轨道永久写回。
- 完整程序生成算法、随机事件权重池、事件链和种子调试 UI。
- 强制倒计时、强制袭击、强迫玩家立即响应的事件。

这些后续系统可以读取本阶段写下的地图、可见性、区域内容、扫描结果、探索奖励和风险标记接口，但第七步不得用临时敌人、临时伤害、临时成长或假回归结算来满足阶段验收。

## 3. 开发依赖顺序

本阶段按以下顺序开发：

1. 明确读取 `ExpeditionState`、单位运行态、矿产点实例、建筑实例、工具装备和当前地表坐标系的入口。
2. 扩展当前远征层数据，加入地图状态、区域状态、战争迷雾格、探索内容实例、扫描任务、发现记录、探索奖励和地图标记。
3. 建立首批区域类型和区域实例，确保空投点、邻近矿区、废墟群、信号点和风险区有稳定 ID。
4. 建立战争迷雾计算规则，区分未知、已探索和当前可见。
5. 接入第五步单位视野、飞行单位侦察和小地图框架。
6. 接入第六步矿产点、建筑、地上物和地表坐标实例，让迷雾和扫描能控制它们的显示状态。
7. 接管 `scout` 指令，完成侦察目标选择、移动意图、区域发现和失败提示。
8. 接管 `scan` 指令，完成扫描目标、扫描范围、进度、控制技能影响和结果写回。
9. 建立废墟、特殊信号、失控设施、拾荒者机器活动区和环境危险区域的内容实例。
10. 建立探索奖励状态，确保奖励位于废墟缓存、地表掉落、单位背包、空投舱货物区或当前远征记录中，不直接写入轨道永久层。
11. 完成地表 HUD、小地图、地图叠层、扫描面板、发现日志和区域详情反馈。
12. 落地并引用本阶段视觉、音效和图标资源。
13. 验证正式流程、调试流程、迷雾状态、扫描结果、奖励位置、地图标记、保存恢复和失败路径。

## 4. 状态入口和写入边界

### 4.1 读取数据

探索、战争迷雾、扫描和区域内容系统读取：

- `GameSession.ActiveExpedition`：当前远征权威入口。
- `ExpeditionState.expedition_id`、`seed`、`target_coordinate`：地图和区域归属。
- `ExpeditionState.active_unit_instance_ids`：可提供视野、侦察和扫描的单位。
- `ExpeditionState.unit_runtime_states`：单位位置、朝向、移动状态和当前命令。
- `ExpeditionState.surface_inventory_ids`：探索奖励落点和地表容器入口。
- `ExpeditionState.mineral_deposit_states`：第六步矿产点实例和耗尽状态。
- `ExpeditionState.ground_item_states`：地表掉落物显示和搬运目标。
- `ExpeditionState.building_instance_ids`：建筑位置、视野源和地图标记。
- `UnitData`、`UnitInstance`、装备和工具道具：单位视野、侦察、扫描和控制能力来源。
- `ItemData`：探索奖励和可带回物定义。
- 第五步 `UnitCommand`：`scout`、`scan`、`hack` 的指令 ID 和目标结构。

### 4.2 写入数据

本阶段允许写入：

- `ExpeditionState.surface_map_state`：地图边界、区域集合、迷雾格和地图标记入口。
- `ExpeditionState.region_states`：区域类型、发现状态、风险等级和内容引用。
- `ExpeditionState.fog_cell_states`：未知、已探索、当前可见、最后可见时间和历史摘要。
- `ExpeditionState.exploration_content_states`：废墟、特殊信号、失控设施、拾荒者机器活动区、环境危险区域和隐藏矿产引用。
- `ExpeditionState.scan_job_states`：扫描来源、目标、进度、结果和失败原因。
- `ExpeditionState.exploration_discovery_records`：区域、对象、奖励和线索发现记录。
- `ExpeditionState.exploration_reward_states`：奖励内容、位置、领取状态和回归前暂存状态。
- `ExpeditionState.discovered_coordinate_states`：隐藏坐标、信号来源和带回后是否可写入轨道的状态。
- `ExpeditionState.map_marker_states`：小地图和地图叠层标记。
- `MineralDepositInstance.is_discovered`、`scan_state`、`last_known_yield_hint` 等揭示字段。
- `UnitInstance.current_command`：侦察和扫描状态摘要。
- `ExpeditionState.surface_command_records`：侦察、扫描和关键发现的审计记录。

本阶段不允许写入：

- 轨道永久库存。
- 轨道蓝图解锁、协议解锁和信用点。
- 回归结算结果和 `RunRecord` 完成记录。
- 战斗伤害、敌对单位死亡、敌对掉落和防御设施伤害。
- 觉醒者熟练度经验、角色成长等级、AI 芯片安装和改装结果。
- 火箭货舱装载结果。

### 4.3 正式入口与调试入口

正式流程必须从当前 `ExpeditionState` 中读取地表坐标、单位、建筑、矿产点和库存状态。地图、迷雾、区域内容和奖励都必须归属当前 `expedition_id`，不得创建脱离远征的全局探索状态。

调试入口可以指定地图种子、起始区域、扫描目标和预置内容，但必须满足：

- 由 `DebugLauncher`、启动参数或调试配置触发。
- `debug_enabled` 为 true。
- 调试创建的区域、奖励和信号使用稳定 ID。
- 日志使用 `[调试]` 前缀。
- 不把调试发现写入轨道永久层。

## 5. 地图、区域和迷雾数据

### 5.1 SurfaceMapState

`SurfaceMapState` 表达当前远征的地表地图状态。

字段建议：

- `map_state_id`
- `expedition_id`
- `seed`
- `target_coordinate`
- `bounds`
- `cell_size`
- `region_ids`
- `drop_zone_region_id`
- `fog_grid_id`
- `map_marker_ids`
- `generation_profile_id`
- `created_by_seed`

规则：

- `expedition_id` 必须等于当前远征 ID。
- `seed` 和 `target_coordinate` 必须来自正式远征创建链路。
- `bounds` 限制镜头、单位移动和扫描目标选择。
- `generation_profile_id` 只表达本阶段的区域布局配置；完整程序生成参数和随机事件权重由第十一步扩展。
- 地图状态可以保存和恢复，不依赖当前场景节点临时状态。

### 5.2 SurfaceRegionState

`SurfaceRegionState` 表达地图上的一个区域。原始设计要求地图以“区域”划分，本阶段以区域作为探索、扫描和风险收益选择的主要单位。

字段建议：

- `region_id`
- `expedition_id`
- `region_type`
- `bounds`
- `center_position`
- `adjacent_region_ids`
- `discovery_state`
- `visibility_state`
- `risk_level`
- `content_instance_ids`
- `primary_marker_id`
- `last_scanned_at`
- `created_by_seed`

`region_type` 首批建议：

- `drop_zone`：空投点和初始安全区域。
- `open_waste`：开放废土和移动通道。
- `mineral_field`：矿产密集区。
- `scrap_yard`：废料和旧设备残骸区。
- `ruin_cluster`：废墟群。
- `signal_site`：特殊信号源附近。
- `facility_perimeter`：失控设施外围。
- `scavenger_activity`：拾荒者机器活动区。
- `hazard_zone`：环境危险区域。

`discovery_state`：

- `unknown`：未探索，玩家不知道区域细节。
- `scouted`：侦察或扫描确认区域存在，但未完全可见。
- `explored`：单位视野进入过区域。
- `surveyed`：扫描完成，主要内容已标记。

规则：

- 初始只揭示空投点区域和单位初始视野范围。
- 邻接关系用于小地图边界、侦察路线和后续程序生成扩展。
- `risk_level` 只用于提示风险，不在本阶段直接造成伤害。
- 区域发现可以创建地图标记，但不能自动创建轨道奖励。

### 5.3 FogCellState

`FogCellState` 表达战争迷雾格。

字段建议：

- `fog_cell_id`
- `expedition_id`
- `grid_position`
- `world_bounds`
- `visibility_state`
- `last_visible_at`
- `last_revealed_by`
- `known_content_ids`
- `last_known_snapshot`

`visibility_state`：

- `unknown`：从未被视野、侦察或扫描揭示。
- `explored`：过去被揭示过，但当前没有友方视野。
- `visible`：当前被单位、建筑或扫描事件看到。

规则：

- 迷雾状态不能删除真实对象，只控制玩家可见性、可交互性和历史信息。
- 当前可见区域显示真实状态。
- 已探索但不可见区域显示最后一次已知状态，必须有“历史信息”表现。
- 未知区域不显示真实对象，只允许显示已经通过扫描得到的模糊标记。
- 小地图必须同步显示三态差异。

### 5.4 VisionSourceState

`VisionSourceState` 表达一个临时或持续视野来源。

字段建议：

- `vision_source_id`
- `expedition_id`
- `source_type`
- `source_id`
- `position`
- `radius`
- `duration`
- `reveal_layers`
- `created_at`

`source_type`：

- `unit`
- `building`
- `scan_pulse`
- `debug`

规则：

- 单位视野随 `SurfaceUnitRuntimeState.position` 更新。
- 飞行单位和侦察型单位可以拥有更高视野或移动揭示效率。
- 建筑可以提供固定视野，但不替代后续防御系统。
- 扫描脉冲可以短时揭示或标记区域，但扫描不等同于永久可见。

## 6. 探索内容实例

### 6.1 ExplorationContentData

`ExplorationContentData` 表达可复用探索内容定义。

字段建议：

- `id`
- `display_name`
- `content_type`
- `description`
- `default_scan_difficulty`
- `required_scan_tags`
- `risk_tags`
- `reward_table_id`
- `marker_icon_path`
- `sprite_path`
- `scan_effect_path`
- `audio_event_id`

`content_type`：

- `mineral_deposit`
- `ruin`
- `special_signal`
- `uncontrolled_facility`
- `scavenger_activity`
- `environment_hazard`

规则：

- `mineral_deposit` 可以引用第六步 `MineralDepositData`。
- `ruin`、`special_signal` 和 `uncontrolled_facility` 可以提供奖励和线索，但不得直接写入轨道永久解锁。
- `scavenger_activity` 和 `environment_hazard` 在本阶段只提供风险标记和后续目标，不直接生成伤害。
- 资源路径必须引用本阶段落地的实际视觉资源，不能只留空占位。

### 6.2 ExplorationContentState

`ExplorationContentState` 表达当前远征中的一个具体探索对象。

字段建议：

- `content_instance_id`
- `content_id`
- `expedition_id`
- `region_id`
- `position`
- `visibility_state`
- `scan_state`
- `linked_object_type`
- `linked_object_id`
- `reward_state_ids`
- `marker_id`
- `risk_level`
- `created_by_seed`
- `failure_reason`

`scan_state`：

- `unscanned`
- `partial`
- `scanned`
- `exhausted`
- `blocked`

规则：

- `linked_object_type=mineral_deposit` 时，`linked_object_id` 必须指向 `MineralDepositInstance`。
- 对象处于 `unknown` 时不能被普通右键直接操作。
- 对象被单位视野揭示后可以创建地图标记。
- 对象完成扫描后可以暴露奖励、隐藏坐标或后续系统目标。
- 对象耗尽或奖励领取后仍保留历史标记，避免玩家重复搜索。

### 6.3 矿产点揭示规则

第六步已经定义 `MineralDepositData` 和 `MineralDepositInstance`，第七步接管矿产点的发现和扫描状态。

规则：

- 未发现矿产点可以存在于当前远征状态中，但不在地表和小地图显示。
- 单位视野进入矿产点范围后，普通矿产点可变为已发现。
- `requires_scan_level` 大于 0 的矿产点必须通过扫描才能显示完整信息。
- 扫描前可以显示模糊矿脉标记；扫描后显示产出道具、剩余量提示、采集难度和推荐工具。
- `gather` 只能作用于已发现且当前可达的矿产点；隐藏矿产点不能被 UI 汇总或全局列表直接采集。
- 扫描不产出矿产道具；矿产道具只能由第六步采集流程产出到单位背包或地上物。

### 6.4 废墟和缓存

废墟是探索奖励和线索的主要承载对象。

废墟首批类型：

- `collapsed_shelter`：坍塌避难所。
- `old_world_terminal`：旧世界终端。
- `broken_factory_node`：损坏工厂节点。
- `abandoned_relay`：废弃中继站。

规则：

- 废墟初次发现只显示外观、风险提示和可扫描状态。
- 扫描可以揭示奖励缓存、蓝图碎片、旧世界芯片、AI 芯片或线索。
- 可搬运奖励必须进入具体位置：废墟缓存库存、地表掉落物、单位背包或空投舱货物区。
- 奖励不能直接进入轨道库存。
- 需要骇入的废墟可以显示 `requires_hack` 状态；具体骇入收益和控制技能成长由后续阶段扩展。

### 6.5 特殊信号

特殊信号用于引导隐藏坐标、数据核心线索、觉醒个体线索和后续事件目标。

字段建议：

- `signal_type`
- `signal_strength`
- `source_region_id`
- `scan_required`
- `linked_coordinate_id`
- `linked_clue_id`
- `decay_rule`

规则：

- 特殊信号可以先以方向、强度或范围形式出现。
- 扫描完成后生成明确地图标记或隐藏坐标线索。
- 隐藏坐标线索写入 `ExpeditionState.discovered_coordinate_states`，回归前不直接成为轨道永久可选坐标。
- 数据核心线索只作为当前远征发现记录或可带回线索道具存在，不直接完成最终目标。

### 6.6 风险区域

拾荒者机器活动区、失控设施和环境危险区域在本阶段作为风险收益选择的一部分出现。

规则：

- 风险区域可以显示活动痕迹、警告标记和建议扫描。
- 本阶段不生成敌对单位巡逻、伤害、炮塔攻击或环境持续伤害。
- 扫描可以标记风险等级、后续战斗目标和可能奖励。
- 第八步接管敌对目标、伤害、行为模式和防御系统。

## 7. 侦察和扫描系统

### 7.1 scout 指令

`scout` 指令用于推动单位进入未探索区域或检查地图标记。

执行规则：

- 目标可以是地面坐标、未知区域边界、地图标记或已发现但未完全调查的区域。
- 单位必须具备移动能力，并处于可控状态。
- 飞行单位、侦察型单位和携带扫描器的单位可以获得更高侦察效率。
- 到达目标附近后，根据单位视野揭示迷雾格和区域状态。
- 如果目标在不可达区域，写入明确 `failure_reason`。
- `scout` 不自动收集奖励、不自动攻击敌人、不自动触发强制事件。

### 7.2 scan 指令

`scan` 指令用于揭示矿产点、废墟、特殊信号和区域内容。

字段建议：

- `scan_job_id`
- `expedition_id`
- `source_unit_instance_id`
- `source_tool_item_id`
- `target_type`
- `target_id`
- `target_position`
- `scan_radius`
- `scan_power`
- `scan_precision`
- `required_scan_tags`
- `progress`
- `state`
- `result_ids`
- `failure_reason`

`state`：

- `queued`
- `in_progress`
- `completed`
- `failed`
- `cancelled`

规则：

- 扫描目标必须来自当前远征的地表目标或地图位置。
- 扫描来源必须是可控单位、携带扫描器或具备扫描能力的单位、调试扫描事件。
- 控制技能可以影响扫描效率、范围或精度，但本阶段不结算技能经验。
- 扫描结果必须写入发现记录、内容状态、地图标记或奖励状态。
- 扫描失败必须说明原因，例如目标不可见、距离不足、缺少扫描工具、区域干扰、目标已经耗尽。
- 扫描不能绕过库存和奖励位置规则。

### 7.3 扫描结果

扫描结果类型：

- `reveal_region`：揭示区域边界、类型或风险等级。
- `reveal_mineral`：揭示隐藏矿产点或矿产点详情。
- `identify_ruin`：识别废墟类型、风险和奖励缓存。
- `trace_signal`：定位特殊信号来源或隐藏坐标。
- `mark_facility`：标记失控设施和后续骇入目标。
- `mark_hazard`：标记环境危险区域。
- `unlock_reward_cache`：显示可搬运奖励或可领取线索。

规则：

- 扫描可以创建 `MapMarkerState`。
- 扫描可以把 `ExplorationContentState.scan_state` 从 `unscanned` 推进到 `partial` 或 `scanned`。
- 扫描可以创建奖励状态，但奖励领取仍要经过具体位置和库存流程。
- 扫描可以暴露后续战斗或骇入目标，但不能在本阶段直接完成战斗或骇入收益。

## 8. 探索奖励和位置规则

### 8.1 ExplorationRewardState

`ExplorationRewardState` 表达当前远征中一个探索奖励。

字段建议：

- `reward_state_id`
- `expedition_id`
- `source_content_instance_id`
- `reward_type`
- `item_id`
- `item_count`
- `clue_id`
- `coordinate_id`
- `location_type`
- `location_id`
- `claim_state`
- `requires_return_to_orbit`
- `failure_reason`

`reward_type`：

- `item_stack`
- `blueprint_fragment`
- `old_world_chip`
- `ai_chip`
- `awakened_clue`
- `data_core_clue`
- `hidden_coordinate`

`location_type`：

- `ruin_cache`
- `ground_item`
- `unit_inventory`
- `drop_pod_cargo`
- `expedition_record`

规则：

- `item_stack`、`blueprint_fragment`、`old_world_chip`、`ai_chip` 属于可带回实体奖励，必须落为 `ItemData`、`ItemInstance` 或明确道具栈，不建立全局奖励数字。
- 可带回实体奖励必须位于 `ruin_cache`、`ground_item`、`unit_inventory` 或 `drop_pod_cargo`，不能只写成抽象发现记录。
- 可搬运奖励必须从具体位置取出，再进入单位背包、空投舱货物区或地表掉落物。
- `awakened_clue`、`data_core_clue`、`hidden_coordinate` 属于记录型线索，可以先进入 `expedition_record`，但只有第十步回归结算后才能决定是否写入轨道永久层。
- 隐藏坐标在本阶段只是当前远征发现，不能绕过回归结算直接解锁轨道坐标。
- 奖励领取失败要写明容量不足、目标不可见、未扫描、缺少工具或对象已耗尽。

### 8.2 奖励领取流程

奖励领取按以下流程执行：

1. 单位或扫描完成后发现奖励。
2. 系统创建 `ExplorationRewardState`，记录奖励来源和位置。
3. 如果奖励是可搬运道具，创建废墟缓存库存、地表掉落物或待取物引用。
4. 玩家通过 `haul`、单位拾取或打开对象详情把奖励移动到具体库存。
5. 回归前奖励仍属于当前远征状态。
6. 第十步火箭回归和结算决定哪些奖励带回轨道。

本阶段不得把奖励直接写入轨道永久库存、蓝图解锁或协议解锁。

## 9. 地表 HUD、地图和反馈

### 9.1 小地图

小地图在第七步从框架变成真实探索信息显示。

小地图必须显示：

- 未知区域。
- 已探索但当前不可见区域。
- 当前可见区域。
- 空投点。
- 当前镜头框。
- 友方单位和建筑。
- 已发现矿产点。
- 已扫描废墟。
- 特殊信号方向或来源。
- 风险区域标记。

规则：

- 小地图点击和拖拽不能穿透到地表指令。
- 未知区域不能显示真实矿产、废墟或敌对内容。
- 已探索区域显示历史标记时必须有区别于当前可见状态的表现。

### 9.2 地图叠层

地图叠层用于查看区域、标记和扫描结果。

功能：

- 区域边界显示。
- 区域类型筛选。
- 风险等级筛选。
- 资源、废墟、信号和风险标记筛选。
- 扫描半径和扫描目标预览。
- 选中标记后显示详情和可用命令。

规则：

- 地图叠层只读展示当前已知信息，不提供全局收取奖励或全局扣除物资入口。
- 对未知区域下达侦察命令时，只能生成 `scout` 或移动意图，不能直接生成采集、领取或攻击结果。

### 9.3 扫描反馈

扫描反馈包括：

- 扫描光圈或脉冲效果。
- 进度条。
- 成功、部分成功和失败音效。
- 扫描结果弹出提示。
- 地图标记新增或更新动画。
- 扫描日志。

规则：

- 扫描 UI 必须显示失败原因。
- 扫描完成后对象详情要区分“已发现”和“已扫描”。
- 多个扫描任务同时存在时，必须能区分来源单位和目标。

### 9.4 发现日志

发现日志记录玩家本轮远征的重要探索结果。

记录内容：

- 区域发现。
- 矿产点发现和扫描。
- 废墟识别。
- 特殊信号定位。
- 风险区域标记。
- 奖励发现和领取。
- 隐藏坐标和线索发现。

规则：

- 发现日志属于当前远征状态。
- 可带回的线索和奖励必须标记是否已经进入可带回位置。
- 发现日志不替代回归结算。

## 12. 给后续系统的接口

### 12.1 给战斗、行为模式和防御系统

第七步输出：

- 当前可见区域和历史探索区域。
- 风险区域标记。
- 失控设施和拾荒者机器活动区实例。
- 地图标记、区域风险等级和特殊信号目标。
- 单位侦察、扫描和发现记录。

第八步接管：

- 敌对单位实例。
- 敌意、警戒、巡逻和追击。
- 武器伤害、命中、受击、死亡和掉落。
- 防御建筑攻击、防御协议和威胁响应。

### 12.2 给角色成长、觉醒者、AI 芯片和改装

第七步输出：

- 扫描记录。
- 骇入目标标记。
- AI 芯片、旧世界芯片和觉醒个体线索奖励状态。
- 控制技能影响扫描效率、范围或精度的入口。

第九步接管：

- 技能经验增长。
- 觉醒者剧情加入。
- AI 芯片安装和效果。
- 改装树、熟练度和角色面板。

### 12.3 给火箭建造、装载、回归和结算

第七步输出：

- 探索奖励状态。
- 线索、芯片、蓝图碎片和隐藏坐标发现记录。
- 当前远征中可带回奖励的位置。

第十步接管：

- 火箭货舱装载。
- 超载、取舍和发射。
- 带回奖励写入轨道永久库存。
- 坐标、蓝图、芯片和线索的永久层结算。

### 12.4 给程序生成、随机事件和复现调试

第七步输出：

- 地图、区域、迷雾和内容实例的数据结构。
- 首批区域类型和内容类型。
- `created_by_seed`、`generation_profile_id` 和调试复现入口。

第十一步接管：

- 完整程序生成算法。
- 随机事件权重池。
- 事件链、环境变化和复现调试 UI。
- 同一种子复现完整地图和关键内容的验收。

## 13. 完成标准

- 地表地图以区域划分，空投点、邻近矿区、废墟、信号点和风险区都有稳定区域状态。
- 战争迷雾具备未知、已探索、当前可见三态，并在地表和小地图同步显示。
- 单位视野和侦察行为能逐步揭示区域。
- `scan` 指令能对矿产点、废墟、特殊信号和区域执行，能写入进度、结果和失败原因。
- 隐藏矿产点只有被视野或扫描揭示后才能成为采集目标。
- 废墟、特殊信号和风险区域能被发现、标记、扫描和记录。
- 探索奖励位于具体位置或当前远征记录中，不直接写入轨道永久库存、蓝图解锁或协议解锁。
- 小地图、地图叠层、扫描反馈和发现日志能展示当前已知信息。
- 本阶段资源已落地并被实际引用。
- Godot headless 能加载项目并进入地表远征，验证地图、迷雾、区域、扫描和 HUD 脚本可实例化。
- 用调试参数直接进入地表时，能验证指定种子、区域揭示、扫描目标和发现记录。
- 不实现敌对伤害、完整随机事件、角色成长、火箭回归和轨道永久结算的临时逻辑。

## 14. 禁止项和常见偏差

- 把探索奖励直接写入轨道永久库存或直接解锁蓝图。
- 用全局资源池、全局奖励数字或 UI 汇总代替具体道具、库存和位置。
- 未发现矿产点出现在可采集列表中。
- 已探索但不可见区域显示实时真实状态，破坏战争迷雾。
- 把随机袭击、强制倒计时或必须立即响应的事件写入第七步验收。
- 用临时敌人、临时伤害或假战斗结果验证风险区域。
- 把角色经验、芯片安装或觉醒者加入提前写入扫描奖励。
- 把完整程序生成、事件权重和种子复现 UI 提前塞入本阶段。
- 小地图点击穿透到地表单位指令。
- 资源文件存在但没有被迷雾、扫描、地图、废墟或信号 UI 实际引用。

## 15. 阶段验收摘要

- 第七步完成地表探索、战争迷雾、扫描和区域内容的正式承载。
- 第七步让玩家必须主动探索才能发现矿产、废墟、特殊信号、风险区域和长期成长线索。
- 第七步输出后续战斗、成长、火箭回归和程序生成所需的地图、区域、内容、标记、奖励和发现记录接口。
- 第七步不把后续系统的战斗、成长、回归和完整随机生成提前做成临时逻辑。
