# 统一库存容器 UI 设计方案

## 1. 目标和依据

本文定义背包、轨道库存、建筑仓库、建筑输入库存、建筑输出库存、施工点库存、空投舱、火箭货舱等界面的统一呈现方式。

设计依据：

- `docs/原始设计.txt`
- `docs/整体策划案.md`
- `docs/2. 统一数据、道具、库存和存档结构.md`
- `docs/UI设计文档.md`
- `docs/UI功能性设计文档.md`

核心目标：

- 所有道具都以同一套视觉语言展示，避免轨道站、地表角色、建筑和货舱各自发明一套库存 UI。
- 玩家能稳定理解“道具在哪个具体位置”，而不是把物资理解成可随处扣除的全局资源。
- UI 组件和代码实现可复用，后续新增容器时只写场景适配，不重写道具格、详情、容量和操作逻辑。
- 保留对象管理的清晰度，但不做成 Windows 文件资源管理器式界面。

## 2. 设计定位

统一库存 UI 的本质是“库存容器界面”，不是单一意义上的“背包界面”。

所有以下位置都应视为 `InventoryContainer` 或等价位置化道具视图：

- `orbit_inventory`：轨道永久库存。
- `unit_inventory`：单位背包。
- `drop_pod_cargo`：空投舱货舱。
- `surface_storage`：地表仓库。
- `building_input`：建筑输入库存。
- `building_output`：建筑输出库存。
- `construction_site`：施工点材料库存。
- `rocket_cargo`：火箭货舱。
- `trade_buffer`：交易确认前的临时缓冲。
- 地上物：不是容器，但可用同一道具格和详情组件展示。

允许借鉴文件浏览器的信息架构：

- 当前所在位置清楚。
- 对象列表或格子清楚。
- 选中对象详情清楚。
- 筛选、排序和分类清楚。
- 从一个位置转移到另一个位置的操作清楚。

禁止借鉴文件浏览器的外观和心智：

- 不使用桌面窗口、文件夹树、路径栏、面包屑文件路径、右键文件菜单等现代操作系统语言。
- 不把道具显示成文件、文件夹或数据表软件。
- 不出现“我的电脑”“磁盘”“目录”等隐喻。
- 不依赖拖拽完成隐式转移；拖拽如果存在，只能作为选择或预览，确认转移仍必须生成明确操作、物流订单或确认记录。

视觉隐喻应来自游戏世界：

- 轨道库存：母舰后勤库存审计终端。
- 单位背包：机体载物仓和工具槽。
- 建筑仓库：地表仓储格。
- 建筑输入 / 输出：生产线进料槽和产出托盘。
- 施工点：施工材料清单和已送达托盘。
- 空投舱 / 火箭货舱：货舱装载审计单。

## 3. 通用组件

### 3.1 道具格

`ItemSlotView` 是最小复用单位。

显示内容：

- 道具图标。
- 堆叠数量。
- 实例道具标记。
- 状态角标：锁定、预留、运输中、输入、输出、施工需求、禁用。
- 品质或分类小色条：矿产、加工产物、芯片、装备、工具、单位平台、蓝图、关键物。
- 可选重量或格位占用提示。

状态覆盖层：

- 预留：青绿色细框或角标。
- 运输中：小型箭头或移动点阵。
- 锁定：冷灰遮罩和锁图标。
- 不可用：低透明遮罩和原因提示。
- 输出阻塞：琥珀角标。
- 错误：锈红角标。

规则：

- 32 px 下能识别类别，48 px 下能识别具体道具。
- 数量显示只表示当前容器中的数量，不表示全局总量。
- 道具格不直接扣除材料；点击只选中或打开操作。

### 3.2 容器头

`InventoryContainerHeaderView` 显示当前容器的身份和约束。

显示内容：

- 容器名称。
- 容器类型：轨道库存、单位背包、仓库、输入库存、输出库存、施工点、空投舱、火箭货舱。
- 所属对象：单位、建筑、空投计划、火箭、轨道站。
- 格位容量。
- 重量容量。
- 允许 / 禁止标签。
- 当前状态：可用、锁定、输出阻塞、等待物流、超重、只读。

容器头必须让玩家知道“我正在看哪个位置的道具”，不能只显示“库存”两个字。

### 3.3 容器内容视图

统一支持三种呈现：

- 格子视图：单位背包、建筑仓库、输入 / 输出槽、施工点、空投舱和货舱优先使用。
- 列表视图：轨道站库存、交易消耗预览、回归结算审计优先使用。
- 双容器视图：搬运、装载、交易确认和转移预览使用。

格子视图适合低容量和空间感；列表视图适合高密度审计；双容器视图适合表达来源和目标。

### 3.4 道具详情

`ItemDetailView` 只显示选中道具的说明和可用操作，不持有业务状态。

显示内容：

- 道具名称、分类、说明。
- 当前所在位置。
- 数量、重量、堆叠限制。
- 用途：可交易、可研发、可空投、可生产、可维修、可装载。
- 限制和失败原因。
- 来源记录入口：可查看来自哪次采集、交易、空投或回归。

### 3.5 操作区

操作区根据容器上下文显示按钮。

常见操作：

- 查看详情。
- 标记为空投候选。
- 加入装载清单。
- 移出装载清单。
- 创建搬运订单。
- 定位来源。
- 定位目标。
- 清空筛选。
- 确认交易。
- 确认转移。

按钮禁用时必须显示原因。

## 4. 场景适配

### 4.1 轨道库存

轨道库存使用高密度列表作为主视图，并允许在后续扩展中切换格子视图。

布局：

```text
容器头：轨道永久库存 / 容量 / 重量 / 筛选状态
列表区：道具图标、名称、分类、数量、重量、价值、标签、状态
详情区：用途、限制、可交易 / 可研发 / 可空投状态
操作区：筛选、排序、标记为空投候选、查看来源
```

轨道库存不是“全局资源池”。它只是 `orbit_inventory` 容器，所有数量都来自该容器。

### 4.2 单位背包

单位背包使用紧凑格子视图。

布局：

```text
容器头：单位名称 / 背包 / 格位 / 重量
格子区：携带道具
详情区：当前选中道具
操作区：丢到地面、搬运到目标、装入货舱、查看来源
```

单位背包只显示该单位携带的道具，不显示基地总物资。

### 4.3 地表仓库

地表仓库使用中型格子视图或列表视图，依据容量决定。

重点：

- 显示仓库所在建筑和位置。
- 显示可搬入、可搬出、预留和阻塞状态。
- 提供物流入口，而不是直接把材料传送到生产建筑。

### 4.4 建筑输入和输出

生产建筑必须把输入库存和输出库存并排呈现。

布局：

```text
左：输入库存
中：生产队列 / 当前配方 / 电力状态
右：输出库存
底部：开始、暂停、取消、循环生产、创建搬运订单
```

规则：

- 配方只从输入库存消耗。
- 产物只进入输出库存。
- 输出库存满时显示 `output_blocked`。
- 仓库或单位背包中的材料必须通过物流订单进入输入库存。

### 4.5 施工点

施工点不是普通仓库，而是“材料需求 + 已送达库存”的组合。

布局：

```text
容器头：施工点 / 建筑名 / 施工进度
需求清单：所需道具、总需求、已送达、缺口
已送达库存：施工点材料库存格子
关联物流：待处理、运输中、阻塞订单
操作区：定位、暂停、取消建造
```

确认放置建筑只创建施工点和材料需求，不扣全局材料。

### 4.6 空投舱

空投舱使用货舱装载审计视图。

重点：

- 当前装载清单使用统一道具格。
- 容器头显示重量、格位、单位容量。
- 右侧或底部显示禁止携带、库存不足、超重、超格和单位容量超限。
- 修改配置态时不扣轨道库存；确认后才创建转移记录。

### 4.7 火箭货舱

火箭货舱使用双容器视图：

- 左侧：可带回位置中的道具。
- 中央：火箭货舱。
- 右侧：遗留预览。

火箭货舱允许显示超载，但必须明确标记风险。回归结算只写回火箭货舱中的道具。

### 4.8 地上物

地上物不是库存容器，但展示仍使用道具格和详情组件。

显示内容：

- 道具图标、数量、位置。
- 来源记录。
- 可搬运目标。
- 是否已被物流订单预留。

## 5. 交互规则

### 5.1 选择和详情

- 单击道具格选中道具。
- 双击不执行不可逆转移。
- 详情面板显示该道具在当前容器中的状态。
- 多选只用于批量创建明确操作，例如批量搬运或批量加入货舱。

### 5.2 转移

转移必须表达来源和目标。

允许的转移方式：

- 直接库存转移：轨道交易、空投确认、火箭装载保存等明确确认场景。
- 物流订单：地表仓库、单位背包、建筑输入、建筑输出、施工点和地上物之间的移动。
- 结算写回：火箭货舱到轨道库存。

禁止：

- UI 从汇总数字直接扣除。
- 拖拽后静默改变库存。
- 生产建筑直接从仓库或单位背包消费材料。
- 输出产物绕过输出库存直接进入仓库。

### 5.3 筛选和排序

筛选和排序只影响显示顺序，不改变容器内容和存档顺序。

筛选维度：

- 分类。
- 标签。
- 可用状态。
- 位置类型。
- 是否预留。
- 是否可空投、可交易、可研发、可生产、可装载。

### 5.4 失败原因

常见失败原因必须显示在容器或操作按钮附近：

- 数量不足。
- 重量超限。
- 格位不足。
- 标签禁止。
- 前置未满足。
- 目标位置不存在。
- 目标已满。
- 道具已预留。
- 物流路径不可达。
- 输出阻塞。
- 容器只读或锁定。

## 6. 代码复用建议

本文不要求立刻实现代码，但后续实现应按以下方向拆分。

基础视图：

- `ItemSlotView`：单个道具格。
- `InventoryContainerHeaderView`：容器头。
- `InventoryGridView`：格子视图。
- `InventoryListView`：列表视图。
- `ItemDetailView`：道具详情。
- `InventoryCapacityView`：容量、重量和格位条。
- `InventoryStatusBadgeView`：锁定、预留、运输中、输出阻塞等角标。

组合视图：

- `InventoryPanelView`：容器头 + 内容 + 详情 + 操作区。
- `InventoryTransferPanelView`：来源容器 + 目标容器 + 转移预览。
- `ProductionInventoryPanelView`：输入库存 + 输出库存 + 生产队列。
- `ConstructionInventoryPanelView`：需求清单 + 施工点库存 + 物流状态。
- `CargoManifestPanelView`：空投舱 / 火箭货舱装载清单。

数据适配：

- `InventoryViewModelBuilder`：把 `InventoryContainer`、`ItemData`、`ItemLocation`、预留状态和上下文转成 UI 只读数据。
- `InventoryActionContext`：描述当前容器允许的操作，不在 UI 控件里硬编码业务规则。
- `InventoryActionResult`：返回成功、失败原因、关联转移或物流订单。

规则：

- UI 不维护第二套库存副本。
- UI 不直接修改 `InventoryContainer`。
- 场景只传入容器 ID、选择上下文和允许操作。
- 所有写入必须走库存服务、物流订单、空投确认、火箭装载或回归结算服务。

## 8. 实施顺序

推荐顺序：

1. 先定义通用道具格、容器头、容量条和状态角标。
2. 轨道站库存页改为使用统一库存列表视图。
3. 地表单位背包和建筑详情改为使用统一格子视图。
4. 生产建筑接入输入 / 输出并排库存面板。
5. 施工点接入需求清单 + 已送达库存面板。
6. 空投配置接入货舱审计视图。
7. 火箭装载接入双容器货舱视图。
8. 物流订单面板接入统一来源 / 目标道具格。

## 9. 验收清单

- 轨道站库存、单位背包、建筑仓库、建筑输入 / 输出、施工点、空投舱、火箭货舱使用同一道具格视觉语言。
- 每个库存面板都显示容器身份、容量、重量或格位限制。
- 道具数量只表示当前容器数量，不表示全局数量。
- 道具详情能显示当前所在位置和可用操作。
- 任何转移都能看见来源、目标和失败原因。
- 地表 HUD 顶部不出现全局矿产总量栏。
- 生产只从建筑输入库存消耗，只向建筑输出库存产出。
- 施工只消耗施工点库存。
- UI 组件不维护第二套库存数据。
- 效果图和最终 UI 不像现代操作系统文件浏览器。

## 10. 禁止项

- 把轨道站、单位背包、建筑仓库分别做成互不兼容的 UI。
- 把背包设计成唯一库存形态，忽略建筑输入、输出、施工点和货舱。
- 使用文件夹树、路径栏、系统窗口按钮等桌面文件管理器语言。
- 用顶部总量栏表达所有矿产和材料。
- 从 UI 汇总数字直接扣材料。
- 允许拖拽后静默转移道具。
- 在生产、施工、空投或回归中绕过 `InventoryTransfer`、物流订单或正式确认链路。
