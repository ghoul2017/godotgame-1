# 第五步策划案：地表 RTS 控制与单位系统

## 1. 目标定位

第五步要把第四步创建的正式远征状态接入地表玩法场景，并完成玩家在地表的核心 RTS 操作体验。玩家需要能看到空投带入的觉醒者和量产机，使用左键选择、框选、多选、右键上下文指令和数字编组来组织单位移动、部署、搬运、维修、扫描、护卫等行动。

本阶段完成后，项目应具备以下能力：

```text
地表远征场景
-> 接收 ExpeditionStartPayloadData
-> 读取 GameSession.ActiveExpedition 和 UnitInstance
-> 根据 UnitData / UnitInstance 实例化地表单位节点
-> 左键单选 / 拖拽框选 / 多单位选择
-> Ctrl + 数字键保存编组，数字键召回编组
-> 右键根据目标解析正式 UnitCommand
-> 单位执行移动、朝向、路径反馈和基础状态显示
-> 把当前指令、行为模式、位置和编组状态写回当前远征层
```

本阶段是地表玩法的操作和单位承载层，不是矿产采集生产、战争迷雾、战斗 AI 或角色成长阶段。采集、建造、扫描、骇入、攻击等指令必须在本阶段拥有稳定 ID、目标结构、可用性过滤和失败原因，但具体道具产出、建筑施工、扫描奖励、战斗伤害和熟练度结算由后续对应步骤接管。

## 2. 系统边界

纳入范围：

- 地表单位节点实例化。
- 单位选择、框选、多选和选择高亮。
- 鼠标右键上下文指令解析。
- 单位移动指令、移动目标反馈和路径反馈。
- 数字键小队编组。
- 单位基础状态显示。
- 单位行为模式字段读取、显示和写回。
- 单位指令队列的基础结构。
- 地表镜头移动和缩放。
- 地表 HUD 的单位面板、命令按钮和编组反馈。
- 本阶段需要的单位精灵、头像、选择圈、指令光标、目标反馈、编组反馈和音效资源。

不在本阶段完整展开：

- 矿产点采集产出、地表仓库和搬运结算。
- 建筑放置、施工进度、生产配方和电力网络。
- 战争迷雾、扫描奖励、区域揭示和小地图真实内容。
- 武器伤害、敌人 AI、防御建筑和自动战斗策略。
- 熟练度经验、觉醒者改装树和 AI 芯片效果。
- 火箭建造、火箭货舱装载和回归结算。

这些系统可以读取第五步写下的单位、选择、指令和行为模式接口；第五步不得用临时资源、临时敌人、假采集点或伪造战斗结果来替代后续系统验收。

## 3. 开发依赖顺序

本阶段按以下顺序开发：

1. 明确地表场景读取的 `ExpeditionStartPayloadData`、`ExpeditionState`、`DropPlan`、`UnitData` 和 `UnitInstance` 字段。
2. 为当前远征增加单位地表运行态、选择态和编组态接口。
3. 建立单位实例化工厂，根据 `active_unit_instance_ids` 创建 `SurfaceUnit` 节点。
4. 建立单位表现资源加载规则，绑定首批正式单位精灵、头像、选择圈和状态图标。
5. 接入统一输入行为，确认 UI 面板优先消费输入后再处理地表选择和指令。
6. 完成单选、追加选择、框选、多单位选择、取消选择和选择圈显示。
7. 完成右键目标解析，把地面、单位、建筑、矿产点、废墟和信号解析成 `UnitCommand`。
8. 完成移动指令、移动目标标记、路径反馈和到达状态写回。
9. 完成数字键编组保存、召回、追加、失效清理和 UI 反馈。
10. 完成底部单位信息面板、命令按钮、行为模式入口和状态提示。
11. 完成本阶段正式资源、音效和 UI 引用。
12. 验证正式入口、调试入口、输入隔离、单位实例化、选择、移动、编组和存档状态写回。

## 4. 状态入口和写入边界

### 4.1 读取数据

地表 RTS 控制与单位系统读取：

- `ScenePayload.ExpeditionStartData`：结构化地表进入载荷。
- `ExpeditionStartPayloadData.expedition_id`：当前远征 ID。
- `ExpeditionStartPayloadData.drop_plan_id`：本轮空投计划 ID。
- `ExpeditionStartPayloadData.seed`：当前远征随机种子。
- `ExpeditionStartPayloadData.target_coordinate`：空投坐标。
- `ExpeditionStartPayloadData.active_unit_instance_ids`：本轮可操作单位实例。
- `ExpeditionStartPayloadData.drop_pod_cargo_inventory_id`：空投货物库存。
- `GameSession.ActiveExpedition`：当前远征权威状态。
- `GameSession.DropPlans[ExpeditionStartPayloadData.drop_plan_id]`：本轮空投计划权威数据。
- `ExpeditionState.active_unit_instance_ids`：实际参与地表的单位实例 ID。
- `ExpeditionState.surface_inventory_ids`：地表库存入口，本阶段只显示引用和状态。
- `GameSession.UnitInstances`：单位实例池。
- `UnitData`：单位定义数据。
- `ItemInstance` 和单位装备引用：用于显示武器、工具和可用指令入口。

### 4.2 地表进入校验

地表场景实例化单位前必须校验 `ExpeditionStartPayloadData`、`GameSession.ActiveExpedition` 和 `DropPlan` 是同一条正式链路。

必须校验：

- `ExpeditionStartPayloadData.expedition_id` 等于 `GameSession.ActiveExpedition.expedition_id`。
- `ExpeditionStartPayloadData.drop_plan_id` 等于 `GameSession.ActiveExpedition.drop_plan_id`。
- `GameSession.DropPlans` 中存在对应 `drop_plan_id`。
- payload 的 `seed` 等于 `ExpeditionState.seed` 和 `DropPlan.seed`。
- payload 的 `target_coordinate` 等于 `ExpeditionState.target_coordinate` 和 `DropPlan.target_coordinate`。
- payload 的 `active_unit_instance_ids` 与 `ExpeditionState.active_unit_instance_ids` 一致，允许排序不同，但不允许缺失、重复或多出单位。
- `ExpeditionState.active_unit_instance_ids` 必须能由 `DropPlan.selected_awakened_unit_instance_ids`、`DropPlan.selected_mass_unit_instance_ids` 和 `DropPlan.created_unit_instance_ids` 推导，不能出现未记录来源的正式单位。
- payload 的 `drop_pod_cargo_inventory_id` 必须存在于 `ExpeditionState.surface_inventory_ids`。
- `drop_pod_cargo_inventory_id` 指向的库存容器必须存在，且 `owner_type` 为 `drop_pod_cargo` 或等价正式类型。
- payload、`DropPlan` 和 `ExpeditionState` 中任一核心字段不一致时，正式流程拒绝进入地表，输出 `[远征]` 错误日志。

调试流程可以放宽坐标或载荷来源，但必须带 `debug_enabled`，并在日志中明确调试数据来源。

### 4.3 写入数据

本阶段允许写入：

- `UnitInstance.current_command`：当前指令摘要。
- `UnitInstance.behavior_mode`：当前行为模式 ID。
- `ExpeditionState.unit_runtime_states`：单位位置、朝向、移动状态和当前命令。
- `ExpeditionState.control_group_states`：当前远征的小队编组。
- `ExpeditionState.surface_command_records`：需要审计的玩家指令记录。
- 地表运行日志中的选择、编组和移动指令结果。

本阶段不允许写入：

- 轨道永久库存。
- 回归结算结果。
- 地表矿产产出。
- 建筑实例和生产进度。
- 战斗伤害、击杀记录和敌对单位掉落。
- 熟练度经验和改装结果。
- 火箭货舱库存。

### 4.4 正式入口与调试入口

正式流程只能通过第四步创建的 `DropPlan -> ExpeditionState -> ExpeditionStartPayloadData` 进入地表。地表场景不得因为缺少单位而自行生成“演示单位”。

调试入口可以构造验证用远征，但必须满足：

- 由 `DebugLauncher`、启动参数或调试配置触发。
- `debug_enabled` 为 true。
- 使用稳定 `unit_id`、`unit_instance_id`、`item_id` 和 `drop_plan_id`。
- 日志使用 `[调试]` 前缀。
- 不把调试单位、调试物资和调试指令写入正式轨道永久层。

## 5. 地表单位运行态

### 5.1 SurfaceUnitRuntimeState

`SurfaceUnitRuntimeState` 保存当前远征中某个单位在地表场景的运行状态。它引用 `UnitInstance`，不替代 `UnitInstance`。

字段建议：

- `unit_instance_id`
- `expedition_id`
- `position`
- `facing_angle`
- `movement_state`
- `current_command_id`
- `command_queue`
- `current_target_id`
- `current_target_position`
- `last_reachable_position`
- `is_selected`
- `is_controllable`
- `selection_group_ids`
- `last_error_code`

规则：

- `unit_instance_id` 必须存在于 `ExpeditionState.active_unit_instance_ids`。
- `position` 必须在当前地表坐标系内。
- `is_selected` 是当前运行态，可存入远征恢复数据，但不影响单位所有权。
- `is_controllable` 由单位归属、耐久、能源、剧情锁定和调试状态共同决定。
- 指令队列保存稳定 `command_id` 和目标引用，不保存目标节点对象。

### 5.2 UnitCommand

`UnitCommand` 表达玩家或行为模式下发的单位指令。

字段建议：

- `command_id`
- `command_type`
- `source_unit_instance_ids`
- `target_type`
- `target_id`
- `target_position`
- `issued_by`
- `issued_at`
- `queue_mode`
- `required_command_tags`
- `validation_state`
- `failure_reason`

`queue_mode`：

- `replace`：替换当前指令。
- `append`：追加到指令队列。
- `interrupt`：中断当前行为并立即执行。

### 5.3 SurfaceCommandRecord

需要复盘的玩家指令写入 `ExpeditionState.surface_command_records`。

字段建议：

- `record_id`
- `expedition_id`
- `command_id`
- `command_type`
- `unit_instance_ids`
- `target_type`
- `target_id`
- `target_position`
- `result`
- `failure_reason`
- `created_at`

用途：

- 调试单位不执行指令的问题。
- 复盘玩家关键操作。
- 后续战斗、采集、建造和扫描系统接入时追踪指令来源。

普通选择变化可以只进入运行日志；编组、移动、护卫、扫描、骇入、攻击等正式指令应能记录成功或失败原因。

## 6. 单位实例化

### 6.1 SurfaceUnitFactory

`SurfaceUnitFactory` 负责把数据层单位实例转成地表节点。

输入：

- `UnitInstance`
- `UnitData`
- `SurfaceUnitRuntimeState`
- 当前空投点。
- 地表单位层节点。

输出：

- `SurfaceUnit` 节点。
- 单位精灵。
- 选择圈。
- 状态条。
- 点击命中区域。
- 单位运行态绑定。

实例化规则：

- 只实例化 `ExpeditionState.active_unit_instance_ids` 中存在且能在 `GameSession.UnitInstances` 找到的单位。
- 找不到 `UnitData` 时创建可识别错误单位节点，并记录 `[数据]` recoverable error；不能静默跳过。
- 同一个 `unit_instance_id` 在地表只能有一个 `SurfaceUnit` 节点。
- 单位初始位置以空投点为中心，按单位碰撞半径和空投顺序分布。
- 飞行单位和地面单位使用同一选择与指令接口，但移动层和避让规则不同。

### 6.2 SurfaceUnit 节点职责

`SurfaceUnit` 只负责单个单位的地表表现和局部状态桥接。

职责：

- 显示单位精灵、头像引用、选择圈和状态条。
- 暴露选择命中范围。
- 接收 `UnitCommand` 执行请求。
- 更新移动、朝向和当前指令状态。
- 将可持久化状态写回 `SurfaceUnitRuntimeState`。

不负责：

- 全局选择列表。
- 右键目标解析。
- 道具产出。
- 建筑施工。
- 战斗伤害结算。
- 存档写入文件。

## 8. 指令类型和目标解析

### 8.1 首批正式指令 ID

| 指令 ID | 显示名 | 目标类型 | 立即执行范围 | 本阶段处理 | 后续接管 |
| --- | --- | --- | --- | --- | --- |
| `move` | 移动 | 地面坐标 | 可移动单位 | 执行移动、路径反馈和到达写回。 | 地形阻挡和区域生成由第 7、11 步扩展。 |
| `stop` | 停止 | 当前单位 | 可控单位 | 清空当前移动目标和指令队列，写回当前指令为空闲。 | 第 8 步扩展为停止自动攻击或停止行为模式覆盖。 |
| `scout` | 侦察 | 地面坐标 / 未探索区域 | 侦察单位或飞行单位 | 作为移动到侦察目标的正式指令，记录侦察意图和目标区域。 | 第 7 步接入视野揭示、战争迷雾和区域发现。 |
| `gather` | 采集 | 矿产点 / 废料对象 | 有采集能力单位 | 生成正式指令、显示不可执行原因或等待矿产采集系统。 | 第 6 步完成道具产出和仓储写入。 |
| `haul` | 搬运 | 道具堆 / 仓库 / 单位库存 | 有搬运能力单位 | 生成正式指令和目标记录。 | 第 6、10 步完成库存搬运和火箭装载。 |
| `build` | 建造 | 建筑蓝图 / 建造点 | 有建造能力单位 | 生成正式指令和命令按钮入口。 | 第 6 步完成建筑放置和施工进度。 |
| `repair` | 修理 | 受损单位 / 建筑 | 有维修能力单位且携带维修工具或具备维修标签 | 可对单位状态显示入口做校验，不结算维修量。 | 第 6、8 步完成维修消耗和战斗后状态。 |
| `attack` | 攻击 | 敌对单位 / 敌对建筑 | 有武器或攻击平台单位 | 生成正式指令和目标光标。 | 第 8 步完成伤害、射程和自动战斗。 |
| `guard` | 护卫 | 友方单位 / 区域 | 可战斗或可护卫单位 | 跟随目标或移动到护卫点。 | 第 8 步扩展威胁响应。 |
| `scan` | 扫描 | 矿产点 / 废墟 / 特殊信号 / 区域 | 有扫描工具或扫描能力单位 | 生成正式指令、显示扫描范围反馈。 | 第 7 步完成揭示、奖励和控制技能影响。 |
| `hack` | 骇入 | 失控设施 / 门禁 / 敌对协议节点 | 具备控制能力单位 | 生成正式指令和失败原因。 | 第 7、8、9 步完成骇入效果和技能成长。 |
| `return_to_repair` | 回到维修点 | 维修站 / 安全点 | 受损或低能源单位 | 生成移动指令到维修点；无维修点时显示失败原因。 | 第 6 步接入维修站，第 8 步接入自动撤退。 |

### 8.2 右键上下文解析

右键指令解析优先级：

1. 点击 UI 时由 UI 消费，不进入地表指令。
2. 点击敌对单位或敌对建筑：尝试 `attack`。
3. 点击友方受损单位或受损建筑：尝试 `repair`。
4. 点击友方单位：尝试 `guard` 或跟随。
5. 点击矿产点、废料或可回收对象：尝试 `gather`。
6. 点击掉落物、仓库或可搬运对象：尝试 `haul`。
7. 点击废墟、特殊信号或未知结构：尝试 `scan`。
8. 点击失控设施或协议节点：尝试 `hack`。
9. 点击可通行地面：执行 `move`。
10. 点击不可达或无效位置：显示失败反馈。

目标解析输出必须包含：

- `target_type`
- `target_id`
- `target_position`
- `preferred_command_type`
- `fallback_command_type`
- `failure_reason`

稳定 `target_type` 和 ID 来源：

| `target_type` | 语义 | `target_id` 来源 | 主要指令 |
| --- | --- | --- | --- |
| `ground_position` | 可通行地面坐标 | 空字符串或坐标哈希；逻辑以 `target_position` 为准 | `move`, `scout`, `guard` |
| `unit_friendly` | 友方单位 | `UnitInstance.unit_instance_id` | `guard`, `repair`, `haul` |
| `unit_hostile` | 敌对单位 | 敌对 `UnitInstance.unit_instance_id` 或后续敌对实例 ID | `attack`, `hack` |
| `building_friendly` | 友方建筑 | `BuildingInstance.building_instance_id` | `repair`, `haul`, `return_to_repair` |
| `building_hostile` | 敌对建筑或失控设施 | `BuildingInstance.building_instance_id` 或后续敌对设施 ID | `attack`, `hack` |
| `mineral_deposit` | 矿产点、矿脉、废料堆 | 后续矿产点实例 ID | `gather`, `scan` |
| `item_stack` | 地表掉落物或可搬运物资堆 | 地表掉落实例 ID 或库存条目引用 | `haul` |
| `storage` | 地表仓库、空投舱货物区或后续火箭货舱入口 | `InventoryContainer.inventory_id` 或建筑实例 ID | `haul` |
| `ruin` | 废墟结构 | 后续区域内容实例 ID | `scan`, `hack` |
| `signal` | 特殊信号或坐标线索 | 后续信号实例 ID | `scan` |
| `protocol_node` | 失控协议节点、门禁或可骇入对象 | 后续协议节点实例 ID | `hack` |
| `invalid` | 无效目标 | 空字符串 | 无 |

后续系统新增目标类型时必须扩展此表或继承现有语义，不能在各系统中临时发明不兼容的 `target_type`。

后续系统没有接入时，不得伪造采集、扫描或攻击结果；只能创建正式指令、显示“目标系统未接入”或“目标不可执行”的明确状态。

### 8.3 多单位指令过滤

多选单位下达指令时必须按单位能力过滤：

- 只给可执行该指令的单位创建命令。
- 不可执行单位保持原指令或进入失败提示列表。
- UI 显示成功数量和失败原因摘要。
- 如果全部单位都不可执行，指令不创建，播放失败反馈。

过滤依据：

- `UnitData.available_commands`
- `UnitInstance.durability`
- `UnitInstance.energy`
- 装备、工具和改装实例标签。
- 单位是否被锁定、瘫痪或剧情不可控。
- 目标系统是否已接入。

## 9. 选择系统

### 9.1 单选

左键点击地表单位时：

- 命中可控单位则清空旧选择并选择该单位。
- 按住追加选择修饰键时，切换该单位选中状态。
- 点击空地且未拖拽时清空选择。
- 点击 UI 时不改变地表选择。

选中后显示：

- 单位选择圈。
- 底部单位信息。
- 头像、名称、耐久、能源、当前指令和行为模式。
- 可用命令按钮。

### 9.2 框选

拖拽框选规则：

- 框选只选择玩家可控单位。
- 默认优先选择屏幕空间内完整或部分落入框选区域的单位。
- 如果框内同时包含觉醒者和量产机，不自动排除任何单位。
- 飞行单位和地面单位都可被框选，但 UI 需要显示移动方式。
- 框选完成后按稳定排序显示单位：觉醒者、重型单位、服务型单位、无人机。

框选视觉：

- 拖拽矩形。
- 命中的单位预高亮。
- 释放鼠标后的选择圈。
- 多单位头像条。

### 9.3 选择状态

`SurfaceSelectionState` 是地表场景运行态。

字段建议：

- `selected_unit_instance_ids`
- `primary_unit_instance_id`
- `last_selected_unit_instance_id`
- `selection_changed_at`
- `selection_source`

规则：

- `selected_unit_instance_ids` 只保存单位实例 ID。
- 单位死亡、离开当前远征或失去控制时必须从选择列表和编组中移除。
- 选择状态可以用于当前远征恢复，但不参与回归结算。

## 10. 编组系统

### 10.1 ControlGroupState

`ControlGroupState` 表达当前远征内的数字编组。

字段建议：

- `group_id`
- `unit_instance_ids`
- `primary_unit_instance_id`
- `created_at`
- `updated_at`

规则：

- 支持 `group_1` 到 `group_9`。
- `Ctrl + 数字键` 保存或覆盖当前选择。
- 数字键选择对应编组。
- 双击数字键或连续按键把镜头移动到编组中心。
- 编组中失效单位自动清理。
- 编组只保存单位实例 ID，不保存节点引用。

### 10.2 编组反馈

UI 必须显示：

- 单位头像上的编组标记。
- 底部多选面板中的编组编号。
- 编组保存成功反馈。
- 编组为空或全部失效的失败反馈。

音效反馈：

- 保存编组。
- 召回编组。
- 编组失效。

## 11. 移动和路径反馈

### 11.1 MovementProfile

`MovementProfile` 可作为 `UnitData` 的字段或独立 Resource。

字段建议：

- `movement_type`
- `max_speed`
- `acceleration`
- `turn_speed`
- `collision_radius`
- `formation_spacing`
- `can_fly`
- `terrain_tags_allowed`
- `terrain_tags_blocked`

首批移动类型：

- `ground_humanoid`：服务型人形单位，普通地面移动。
- `ground_heavy`：重型多足单位，速度慢、碰撞半径大。
- `flying`：无人机飞行移动，可越过地面阻挡，但仍受地图边界限制。

### 11.2 移动指令执行

移动流程：

```text
玩家右键地面
-> ContextCommandResolver 输出 move
-> CommandDispatcher 按单位能力过滤
-> SurfaceUnit 写入 UnitCommand
-> UnitMovementAgent 计算目标位置
-> 单位移动并显示路径 / 目标反馈
-> 到达后写回 SurfaceUnitRuntimeState 和 UnitInstance.current_command
```

基础移动必须满足：

- 多单位移动时按阵型偏移分配目标点。
- 单位不能因为同一目标点完全重叠。
- 目标不可达时显示失败原因。
- 飞行单位和地面单位使用不同可达性规则。
- 镜头移动不影响世界坐标计算。

### 11.3 路径反馈

需要显示：

- 移动目标标记。
- 单位移动路径线。
- 多单位目标阵型点。
- 不可达位置提示。
- 到达反馈。

路径反馈必须从真实指令状态读取，不使用固定动画假装单位执行成功。

## 12. 行为模式入口

第五步只建立行为模式的选择、显示和写回入口，完整自动战斗策略在第 8 步展开。

首批行为模式 ID：

| ID | 显示名 | 本阶段含义 | 后续扩展 |
| --- | --- | --- | --- |
| `balanced` | 均衡 | 默认模式，按玩家指令执行，不主动覆盖命令。 | 第 8 步接入威胁响应。 |
| `work` | 作业优先 | 面向采集、建造、维修和搬运单位，UI 中作为工作倾向显示。 | 第 6、8 步接入低威胁继续工作规则。 |
| `hold` | 固守 | 不主动远离指定区域，本阶段仅显示和写回。 | 第 8 步接入防御半径和目标选择。 |
| `guard` | 护卫 | 跟随或保护指定单位，本阶段可作为护卫指令的持续状态。 | 第 8 步接入自动拦截。 |
| `scout` | 侦察 | 面向无人机，优先移动和扫描入口。 | 第 7 步接入探索、迷雾和扫描。 |
| `support` | 支援 | 面向重型运输和矿工单位，优先承载、维修、护卫和重型工具入口。 | 第 6、8 步接入重型搬运、阵地支援和火炮平台策略。 |
| `return_repair` | 撤退维修 | 低耐久或玩家命令返回维修点，本阶段生成移动目标。 | 第 6、8 步接入维修站和自动撤退阈值。 |

行为模式字段必须写入 `UnitInstance.behavior_mode`，并在单位面板显示。没有接入的自动行为必须显示为“模式已设置，自动逻辑待对应系统接管”，不得在正式流程里伪造战斗或采集效果。

## 13. 地表 HUD 和输入隔离

### 13.1 地表 HUD 布局

地表 HUD 延续第一步的《魔兽争霸》式清晰操作区：

- 顶部状态栏：远征 ID、种子、空投坐标、当前提示。
- 左下小地图区域：本阶段显示框架、镜头视野框和空投点标记；真实迷雾和地图内容由第 7 步接入。
- 底部单位信息面板：头像、名称、耐久、能源、当前指令、行为模式、装备摘要。
- 底部多选头像条：显示当前选择单位。
- 右下命令区：移动、停止、采集、搬运、建造、护卫、修理、攻击、侦察、扫描、骇入、回到维修点等命令按钮。
- 右侧消息区：选择、指令、失败原因和调试提示。

### 13.2 输入优先级

输入处理优先级：

1. 弹窗和确认框。
2. 地表 HUD 命令区、单位面板、小地图和消息区。
3. 拖拽框选。
4. 单位点击选择。
5. 右键上下文指令。
6. 镜头移动和缩放。
7. 调试输入。

任何 UI 消费的输入都不得继续传给地表选择或右键指令。

### 13.3 命令按钮

命令按钮读取当前选择单位的交集能力：

- 所有选中单位都可执行：按钮可用。
- 部分单位可执行：按钮可用，但详情显示可执行数量。
- 无单位可执行：按钮禁用并显示原因。
- 后续系统未接入：按钮可显示锁定或等待接管状态，但必须保留正式 `command_id`。

## 14. 镜头控制

`SurfaceCameraController` 负责地表镜头。

能力：

- 键盘平移。
- 鼠标边缘或中键拖拽平移。
- 鼠标滚轮缩放。
- 召回编组时镜头移动到编组中心。
- 限制镜头不离开当前地图边界。

镜头状态建议字段：

- `position`
- `zoom`
- `follow_group_id`
- `last_focus_unit_instance_id`

镜头状态属于地表运行态，可用于继续当前远征；不影响单位逻辑和结算。

## 17. 与后续系统的接口

### 17.1 给地表矿产、物品物流、建造、生产和电力系统

第五步输出：

- 单位选择系统。
- `gather`、`haul`、`build`、`repair` 指令 ID 和目标结构。
- 单位移动、到达和当前指令状态。
- 单位能力过滤结果。
- 地表 HUD 命令按钮入口。

第六步接管：

- 矿产点数据和产出。
- 仓库、搬运和库存写入。
- 建筑蓝图、施工进度和维修消耗。
- 电力状态对单位和设施的影响。

### 17.2 给探索、战争迷雾、扫描和区域内容

第五步输出：

- `scan`、`hack`、`scout` 指令 ID 和目标结构。
- 无人机、扫描器和控制能力过滤入口。
- 镜头、小地图框架和空投点标记。

第七步接管：

- 战争迷雾和视野揭示。
- 区域内容、废墟、矿产点和特殊信号生成。
- 扫描结果、奖励和隐藏坐标发现。

### 17.3 给战斗、行为模式和防御系统

第五步输出：

- `attack`、`guard`、`hold`、`return_to_repair` 指令与 `return_repair` 行为模式入口。
- 选中单位、目标解析、移动和基础状态面板。
- 武器 / 工具标签过滤入口。

第八步接管：

- 射程、命中、伤害、敌意、威胁响应和防御建筑逻辑。
- 自动战斗行为模式。
- 低耐久撤退维修策略。

### 17.4 给角色成长、觉醒者、AI 芯片和改装

第五步输出：

- 觉醒者与量产机在选择、编组、指令和状态面板中的差异入口。
- 单位执行指令记录。
- 行为模式和装备摘要显示。

第九步接管：

- 熟练度经验增长。
- 觉醒者专长、改装件和 AI 芯片效果。
- 角色面板深层信息和改装操作。

### 17.5 给火箭建造、装载、回归和结算

第五步输出：

- 单位移动到目标位置。
- `haul` 和 `return_to_repair` 指令接口。
- 当前远征单位位置、状态和编组。

第十步接管：

- 火箭组装坪、货舱装载、发射确认和回归结算。
- 觉醒者和实例道具进入火箭货舱的选择与校验。

## 18. 验收标准

第五步完成时，应满足：

- 地表远征场景只能从结构化 `ExpeditionStartPayloadData` 和当前 `ExpeditionState` 读取正式单位数据。
- 进入地表前会校验 payload、`GameSession.ActiveExpedition` 和 `DropPlan` 的远征 ID、空投计划 ID、种子、坐标、单位实例集合和 `drop_pod_cargo_inventory_id` 一致。
- payload 的 `drop_pod_cargo_inventory_id` 必须存在于 `ExpeditionState.surface_inventory_ids`，否则正式流程拒绝进入地表。
- 地表场景不会因缺少单位而自行生成正式流程演示单位。
- `ExpeditionState.active_unit_instance_ids` 中的单位能根据 `UnitData` 和 `UnitInstance` 实例化为地表单位节点。
- 找不到 `UnitData`、定义数据或实例 ID 时有明确错误对象、日志和 UI 提示。
- 首批五类单位都有正式地表精灵、头像、选择圈和基础状态显示。
- 左键单选可用。
- 拖拽框选可用。
- 多单位选择可用。
- 点击 UI 不会穿透触发地表选择或右键指令。
- 右键地面能创建并执行 `move` 指令。
- 多单位移动会分配阵型目标点，单位不会全部堆在同一坐标。
- 移动目标、路径线、到达反馈和不可达反馈可见。
- 右键单位、矿产点、建筑、废墟、特殊信号和无效目标时能解析出稳定目标结构和明确失败原因。
- `stop`、`scout`、`gather`、`haul`、`build`、`repair`、`attack`、`scan`、`hack` 等指令有稳定 ID、按钮入口、目标结构和能力过滤，不伪造后续效果。
- 数字键 `1` 到 `9` 能召回编组。
- `Ctrl + 数字键` 能保存或覆盖编组。
- 编组单位失效后能自动清理。
- `ExpeditionState.control_group_states` 能保存、恢复和清理当前远征编组。
- `ExpeditionState.surface_command_records` 能记录关键指令的成功、失败原因、目标类型和单位实例 ID。
- `target_type` 使用本文定义的稳定枚举和 ID 来源，不在后续系统中临时发明不兼容目标类型。
- 底部单位信息面板能显示名称、头像、耐久、能源、当前指令、行为模式和装备摘要。
- 行为模式能读取、切换并写回 `UnitInstance.behavior_mode`。
- `UnitInstance.current_command` 和 `SurfaceUnitRuntimeState` 能反映当前移动或指令状态。
- 指令失败有明确 UI 提示和日志，不静默失败。
- 地表镜头可以平移、缩放和聚焦编组。
- 调试入口与正式入口隔离，并标记 `debug_enabled`。
- 本阶段新增图片资源和音效已落地并被实际界面、单位节点或指令流程引用。
- 缺失图标、纯色块、通用占位精灵和静音音效不能用于满足本阶段资源验收。
- `dotnet build` 通过。

- Godot headless 能加载项目并进入地表远征场景，确认单位脚本可实例化。

## 19. 风险点

需要优先避免的问题：

- 地表场景绕过 `ExpeditionState` 自行生成单位，导致空投配置和单位所有权失真。
- 选择系统保存节点引用而不是 `unit_instance_id`，读档、重载或单位销毁后状态失效。
- 右键指令直接在各单位脚本里分散判断，后续采集、建造、战斗接入时难以维护。
- 多单位指令不做能力过滤，导致无人机执行重型建造、服务型单位执行不存在的骇入等错误。
- 地表 HUD 点击穿透到地表指令，造成玩家操作 UI 时单位移动。
- 用假矿产点、假敌人或假采集结果验证按钮，污染后续系统边界。
- 行为模式只做 UI 文本，不写回 `UnitInstance`，后续战斗和角色系统无法读取。
- 资源文件存在但没有被单位节点、HUD、指令按钮或音效流程实际引用。

处理原则：

- 以 `ExpeditionState.active_unit_instance_ids` 和 `UnitInstance` 为单位所有权权威来源。
- 节点表现和数据状态分离，节点只持有 ID 和运行态引用。
- 输入、选择、目标解析、指令派发和单位执行分层处理。
- 本阶段完成真实移动和真实状态写回；后续系统效果只建立正式接口和失败原因。
- UI 输入优先消费，地表指令只处理未被 UI 消费的输入。
- 每个首批单位、指令和反馈资源都要被实际引用后才算完成。
