# 整体策划案

## 1. 项目定位

本项目是一款 PC 单人生存探索 / RTS 游戏，采用 Godot 4.6 .NET 开发，运行时代码默认使用 C#，2D 俯视视角。玩家扮演觉醒的民用家政机器人“灵巧”，从轨道母舰空投到废弃行星地表，围绕探索、建造、生存、回收、回归轨道展开多轮远征。

游戏的最终目标是形成完整的“轨道永久成长 + 地表轮次远征”结构。轨道站是传承层，负责库存、交易、研发、角色管理和空投准备；地表是轮次体验，负责 RTS 操作、资源采集、基地建设、探索、战斗、火箭返航和收益取舍。

核心循环：

```text
轨道站准备 -> 选择空投坐标 -> 空投进入地表
-> 地表探索 / 建造 / 生存 / 战斗 -> 建造并装填火箭
-> 回归轨道 -> 交易与解锁 -> 再次空投
```

设计原则：

- 玩法一致性优先，所有系统服务“探索 -> 建造 -> 回归 -> 再远征”。
- 主动探索驱动，不做强制倒计时式压迫。
- 战斗强调部署、装备、行为模式和准备，不强调高 APM 手操技能。
- 轨道站不是线性升级树，而是通过资源消耗换取新选择。
- 内容可以分阶段开发，但每个阶段都按最终系统形态设计，不用临时玩法逻辑替代最终结构。

## 2. 开发总顺序

整体开发按最终目标拆为 12 个顺序模块。顺序依据是系统依赖关系，而不是功能重要性。

1. 基础工程、输入和场景流程。
2. 统一数据、道具、库存和存档结构。
3. 轨道站主框架。
4. 空投配置与远征创建。
5. 地表 RTS 控制与单位系统。
6. 地表资源、建造、生产和电力系统。
7. 探索、战争迷雾、扫描和区域内容。
8. 战斗、行为模式和防御系统。
9. 角色成长、觉醒者、AI 芯片和改装。
10. 火箭建造、装载、回归和结算。
11. 程序生成、随机事件和复现调试。
12. 长期目标、美术音频和完整内容集成。

### 2.1 每步资源落地原则

每个开发步骤都必须生成并落地当步实际需要的最终取向资源图片、音频反馈和数据资源，不把美术、音频、图标和数据资源集中推迟到最后。每一步交付的内容都是最终系统的一部分，可以在后续步骤扩展数量和覆盖面，但不能以简化版、占位块、缺失图标或临时 UI 代替真实资源。第 12 步负责完整内容集成、风格统一、全局一致性验收和最终反馈整合，不作为首次引入资源的阶段。

各步骤资源交付要求：

1. 基础工程、输入和场景流程：落地主入口、轨道站、地表和结算的基础场景资源；生成第一批实际 UI 皮肤、默认字体配置、基础按钮图标、场景背景图和基础音效资源；只预留新游戏流程的路由和载荷接口，不交付后续正式玩法内容。
2. 统一数据、道具、库存和存档结构：落地首批正式 `Resource` 数据；为首批道具、单位、建筑、空投舱、技能、事件生成实际图标、精灵、头像、预览图，并建立资源引用字段和资源缺失兜底规则。
3. 轨道站主框架：落地轨道站 UI 面板、页签图标、分类图标、按钮状态、列表行样式和信息密度基准。
4. 空投配置与远征创建：落地空投舱图标、空投舱示意图、坐标点视觉、容量 / 重量提示资源和空投确认反馈。
5. 地表 RTS 控制与单位系统：落地单位可识别精灵、头像、选择圈、指令光标、移动目标反馈和编组选中反馈。
6. 地表资源、建造、生产和电力系统：落地资源点、建筑精灵、建筑图标、建造预览、施工状态、受损状态、电力状态和生产反馈资源。
7. 探索、战争迷雾、扫描和区域内容：落地战争迷雾视觉、扫描效果、资源点揭示、废墟外观、特殊信号和区域标记资源。
8. 战斗、行为模式和防御系统：落地武器效果、命中特效、受击反馈、行为模式图标、防御建筑状态和威胁提示资源。
9. 角色成长、觉醒者、AI 芯片和改装：落地觉醒者头像、角色面板图标、技能图标、芯片图标、改装件图标和改装预览资源。
10. 火箭建造、装载、回归和结算：落地火箭组装坪、火箭阶段外观、货舱图标、超载提示、发射反馈和结算图标资源。
11. 程序生成、随机事件和复现调试：落地生成调试可视化资源、事件图标、区域类型标记和种子复现日志展示资源。
12. 长期目标、美术音频和完整内容集成：整合前面所有资源，统一风格，验收关键目标、角色、事件、音频反馈和全局资源一致性；新游戏后的正式内容按地表 HUD、角色、建筑、事件和目标提示承载，不新增独立图片页作为正式界面。

## 3. 基础工程、输入和场景流程

### 3.1 开发目标

建立完整项目骨架，让所有后续模块都能挂接到明确的入口、场景、输入和调试流程中。

### 3.2 功能范围

项目入口：

- `project.godot` 配置有效主入口场景。
- 配置 Godot .NET 项目文件，运行时代码默认使用 C#。
- 主入口只负责初始化、全局服务注册、存档加载和场景切换。
- 玩法逻辑放到轨道站、地表远征、结算等具体场景。

核心场景：

- 轨道站场景：永久库存、交易、研发、角色、空投配置。
- 地表远征场景：地图、单位、建筑、资源、探索、战斗、火箭。
- 回归结算场景：火箭货舱、远征收益、损失、轨道库存写入。

输入系统：

- 左键选择单位和 UI。
- 右键下达上下文指令。
- 鼠标拖拽框选单位。
- 数字键小队编组和选择。
- 快捷键打开建造、库存、地图、行为模式、角色面板。
- 所有输入统一配置到 Input Map。

调试入口：

- 指定远征种子启动地表。
- 指定空投配置进入地表。
- 快速打开轨道站指定页签。
- 打印远征创建、回归结算、库存变化、生成种子日志。

### 3.3 完成标准

- 正式主入口只提供继续游戏、新游戏、设置和退出；轨道站由游戏流程、读档恢复或回归结算进入。
- 第一步只预留新游戏流程的路由、载荷和状态接口，不验收后续正式玩法内容。
- 调试入口能直接复现轨道站、地表远征和回归结算等基础场景路由。
- 输入行为集中配置，可被地表和 UI 共同使用。
- 调试入口不混入正式主入口按钮。

## 4. 统一数据、道具、库存和存档结构

### 4.1 开发目标

先确定所有系统共用的数据形态，保证地表制造、火箭装载、轨道库存、交易研发、角色改装使用同一套道具体系。

### 4.2 功能范围

Resource 数据：

- `ItemData`：道具 ID、名称、分类、重量、堆叠、图标、描述、标签。
- `UnitData`：单位类型、基础属性、移动方式、可用装备、行为能力。
- `BuildingData`：建筑占地、成本、耗电、产出、功能、建造时间。
- `RecipeData`：输入、输出、制造时间、制造设施、能耗。
- `SkillData`：技能类型、经验阈值、等级效果。
- `EventData`：触发条件、权重、风险、奖励、叙事文本。
- `DropConfig`：空投舱容量、初始单位、携带物资、目标坐标。

道具分类：

- 基础资源：金属、硅、稀土、能源块、废料。
- 高级资源：合金、电子元件、纯净数据。
- 终极目标：数据核心。
- AI 芯片：机器人意识、改装和养成基础。
- 改装件：移动、装甲、工具臂、武器接口、传感器。
- 武器：实弹武器、能量武器、EMP 发射器、火炮平台。
- 工具：采矿钻机、维修工具、扫描器、骇入设备。
- 单位物品：量产机机体、无人机平台、重型机器人平台。

库存层级：

- 单位携带库存。
- 地表仓库库存。
- 火箭货舱库存。
- 轨道永久库存。
- 交易和研发消耗库存。

存档结构：

- 轨道永久数据：库存、信用点、蓝图、协议、觉醒者、剧情进度。
- 当前远征数据：种子、空投配置、地图状态、单位、建筑、库存、火箭状态。
- 轮次记录：带入物资、带回物资、损失单位、发现内容、回归时间。

### 4.3 完成标准

- 所有资源、装备、芯片、工具、单位和建筑材料都能进入统一道具体系。
- 地表、火箭、轨道和交易不会各自维护互不兼容的库存结构。
- 存档能表达永久层和当前远征层。

## 5. 轨道站主框架

### 5.1 开发目标

先搭建最终目标中的永久成长层。轨道站是每轮远征的起点和终点，需要尽早确定信息架构。

### 5.2 功能范围

轨道站页面：

- 库存页：查看永久资源、装备、芯片、工具、单位平台。
- 交易页：用资源或信用点交换蓝图、装备、芯片、协议。
- 研发页：解锁高级建筑、先进武器、无人机协议、深空探测模块、空投舱改进。
- 角色页：查看觉醒者状态、技能、装备、改装路线。
- 空投页：选择空投坐标、空投舱、初始单位和携带物资。

轨道经济：

- 信用点作为轨道交易货币。
- 基础资源可直接参与交易。
- 纯净数据和数据核心用于高价值解锁。
- 交易不是线性升级树，而是提供新的远征选项。

轨道 UI：

- 全屏功能界面。
- 信息密度参考《远行星号》。
- 支持分类、筛选、对比、确认和撤销。
- 重点服务准备决策，不做营销式首页。

### 5.3 完成标准

- 玩家能在轨道站查看库存、角色、可交易内容、可解锁内容和空投配置。
- 轨道站能读取永久存档，也能接收回归结算写入的新资源。
- 解锁内容会影响地表可用建筑、装备、协议和空投能力。

## 6. 空投配置与远征创建

### 6.1 开发目标

建立从轨道站进入地表的完整准备流程，让玩家每次远征前都能做出明确取舍。

### 6.2 功能范围

空投配置：

- 选择空投坐标。
- 选择空投舱类型。
- 选择携带资源、装备、工具、芯片。
- 选择初始单位和觉醒者。
- 计算空投容量、重量和限制。

远征创建：

- 生成远征 ID。
- 记录随机种子。
- 写入初始单位、初始物资、坐标和目标。
- 创建地表地图和空投点。

初始远征内容：

- 主角“灵巧”作为默认觉醒者。
- 量产机可作为空投携带单位。
- 碎石在后续新游戏叙事流程中加入。

### 6.3 完成标准

- 轨道站空投配置能创建地表远征。
- 地表能准确生成玩家选择的单位、物资和起始位置。
- 空投限制能迫使玩家在资源、装备和单位之间取舍。

## 7. 地表 RTS 控制与单位系统

### 7.1 开发目标

完成地表的核心操作体验，让玩家以 RTS 方式控制觉醒者和量产机。

### 7.2 功能范围

RTS 操作：

- 左键单选。
- 鼠标框选。
- 多单位选择。
- 右键上下文指令。
- 小队快捷键。
- 选择组高亮、路径反馈、目标反馈。

单位类型：

- 主角“灵巧”：服务型觉醒者，可持用多数人类遗留装备，擅长设施互动。
- 服务型量产机器人：人型工具单位，可持枪械和工具，不成长。
- 轻型运输无人机：飞行、侦察、轻量搬运，生存力低。
- 重型运输机器人：多足蜘蛛结构，高载重，可搭载钻机或火炮平台，维修成本高。
- 觉醒者英雄：拥有技能、成长、改装和背景事件。

单位指令：

- 移动。
- 采集。
- 搬运。
- 建造。
- 修理。
- 攻击。
- 护卫。
- 扫描。
- 骇入。
- 回到维修点。

单位状态：

- 耐久。
- 能源。
- 携带库存。
- 当前指令。
- 行为模式。
- 装备和改装件。

### 7.3 完成标准

- 地表操作符合 RTS 基本预期。
- 不同单位承担不同职责。
- 玩家可以通过编组、部署和指令队列组织基地运转与探索行动。

## 8. 地表资源、建造、生产和电力系统

### 8.1 开发目标

完成地表临时基地的核心生产体系，让玩家能围绕返航目标建立采集、加工、防御和火箭生产能力。

### 8.2 功能范围

资源系统：

- 基础资源：金属、硅、稀土、能源块、废料。
- 高级资源：合金、电子元件、纯净数据。
- 资源点可被单位采集、建筑采集或废墟回收获得。

建筑系统：

- 维修站。
- 组装机。
- 太阳能板。
- 风力发电机。
- 电池组。
- 储罐。
- 仓库。
- 围墙。
- 自动炮塔。
- 火箭组装坪。

生产系统：

- 地表制造基础零部件。
- 制造弹药、简易武器、量产机、建筑模块。
- 配方由 `RecipeData` 配置。
- 生产受资源、电力、建筑状态和单位操作影响。

电力系统：

- 发电、耗电、储能。
- 电力不足影响生产、防御和维修。
- 电池组提供缓冲。

### 8.3 完成标准

- 玩家可以建立临时基地并维持运行。
- 基地生产链能支撑探索、战斗、防御和火箭建造。
- 地表制造与轨道解锁共用同一套道具和蓝图定义。

## 9. 探索、战争迷雾、扫描和区域内容

### 9.1 开发目标

完成地表远征的主要内容来源，让每轮远征都有资源发现、废墟探索、信号调查和风险收益选择。

### 9.2 功能范围

战争迷雾：

- 初始地图被遮蔽。
- 单位视野揭示区域。
- 已探索但当前不可见区域保留历史信息。
- 小地图同步显示探索状态。

探索对象：

- 资源点。
- 废墟。
- 特殊信号。
- 失控设施。
- 拾荒者机器活动区。
- 环境危险区域。

扫描系统：

- 扫描资源点。
- 扫描废墟结构。
- 扫描特殊信号。
- 控制技能影响扫描效率、范围或精度。

探索奖励：

- 蓝图碎片。
- 旧世界芯片。
- AI 芯片。
- 觉醒个体线索。
- 数据核心线索。
- 隐藏坐标。

### 9.3 完成标准

- 玩家需要主动探索才能获得关键资源和长期成长线索。
- 探索收益、风险和路径选择清晰。
- 随机事件只提供变化，不强迫玩家立即响应。

## 10. 战斗、行为模式和防御系统

### 10.1 开发目标

完成以部署和行为模式为核心的战斗体系。玩家不直接频繁释放技能，而是通过装备、位置、维修、防御设施和行为策略决定胜负。

### 10.2 功能范围

敌对内容：

- 野生防御协议。
- 失控炮塔。
- 旧设施守卫。
- 拾荒者机器。
- 环境触发型威胁。

武器类型：

- 枪械。
- 火炮平台。
- 能量武器。
- EMP 发射器。
- 工具型武器。

行为模式：

- 固守：保持阵地，优先保护指定区域。
- 游击：保持距离，自动拉扯。
- 采集优先：低威胁下继续执行资源任务。
- 护卫：跟随并保护指定单位或运输队。
- 撤退维修：耐久过低时自动返回维修点。

防御体系：

- 围墙阻挡。
- 自动炮塔防守。
- 传感器预警。
- 维修站维持持久战。

### 10.3 完成标准

- 战斗结果主要由部署、装备、行为模式和维修保障决定。
- 自动战斗行为可预期，失败原因可从准备和策略上解释。
- 战斗服务探索和基地防御，不变成高 APM 动作系统。

## 11. 角色成长、觉醒者、AI 芯片和改装

### 11.1 开发目标

完成觉醒者作为长期角色资产的成长体系，并让量产机和觉醒者形成清晰差异。

### 11.2 功能范围

主角“灵巧”：

- 型号为民用家政仿人机器人。
- 性格跳脱。
- 擅长精细操作、设施互动和多类型装备使用。

熟练度技能：

- 工程：建造速度、修理效率、火箭制造加成。
- 射击：射击武器使用效能。
- 挖矿：采矿、探矿、资源回收效能。
- 控制：骇入、通信、扫描工具效能。

觉醒者：

- 后期规模控制在 5-10 人。
- 每名觉醒者拥有背景、专长、技能倾向和改装路线。
- 碎石是初期关键觉醒者，定位为矿工和重型运输特化。

AI 芯片和改装：

- AI 芯片是机器人意识、改装和养成基础。
- 改装件影响移动、装甲、工具臂、武器接口、传感器和专用能力。
- 觉醒者可成长、可改装；量产机可制造、可购买、可消耗，但不成长。

### 11.3 完成标准

- 角色通过实际行动积累熟练度。
- 觉醒者具备长期培养价值。
- 改装件和 AI 芯片能显著改变远征构筑。

## 12. 火箭建造、装载、回归和结算

### 12.1 开发目标

完成地表远征的结束机制和收益取舍。火箭不是单纯胜利按钮，而是决定“带走什么、放弃什么”的核心系统。

### 12.2 功能范围

火箭建造：

- 火箭组装坪为固定大型建筑。
- 火箭建造消耗大量材料和能源块。
- 建造耗时以游戏内天数或生产周期表达。
- 工程技能影响制造效率。

装载系统：

- 火箭拥有基础载重。
- 资源、装备、芯片、觉醒者和关键物品都占用载重。
- 超载导致燃料消耗指数上升。
- 玩家确认货舱清单后才能发射。

回归结算：

- 带回物资进入轨道库存。
- 觉醒者回到轨道角色列表。
- 缴获芯片和蓝图进入交易 / 研发可用范围。
- 未带走的装备、资源和量产机遗留在地表。
- 支持后续再次空投同一区域时读取遗留状态。

### 12.3 完成标准

- 玩家能主动决定何时返航。
- 火箭载重造成明确取舍。
- 回归结算准确更新轨道永久层。
- 地表轮次和轨道成长形成闭环。

## 13. 程序生成、随机事件和复现调试

### 13.1 开发目标

完成远征区域的可重复游玩能力，同时保证所有随机内容可用种子复现。

### 13.2 功能范围

程序生成：

- 地形区域。
- 资源分布。
- 废墟布局。
- 特殊信号位置。
- 敌对设施。
- 巡逻点。
- 环境危险区。

随机事件：

- 防御协议激活。
- 环境灾害。
- 拾荒者机器接触。
- 稀有蓝图发现。
- 觉醒者线索。
- 深空坐标碎片。

生成约束：

- 基础资源必须有稳定来源。
- 火箭材料不能完全依赖高风险区域。
- 稀有奖励可以随机，主循环关键资源不能被随机阻断。
- 每次远征保存种子、生成参数和关键生成结果。

调试能力：

- 输入种子复现地图。
- 指定资源密度。
- 指定废墟和事件类型。
- 输出生成日志。
- 输出远征结算日志。

### 13.3 完成标准

- 多轮远征具备明显变化。
- 同一种子能复现地图和关键内容。
- 随机事件增加变化但不破坏玩家主动节奏。

## 14. 长期目标、美术音频和完整内容集成

### 14.1 开发目标

将系统内容包装成完整游戏体验，建立主角动机、世界观、长期目标和最终美术音频方向。

### 14.2 功能范围

新游戏叙事流程：

- 主角购买武装与单程空投舱，进入秘密坐标区域。
- 主角未找到数据核心。
- 主角发现被困矿工觉醒者“碎石”。
- 主角分享残余能源救助碎石。
- 碎石带领主角返回临时基地。
- 新游戏叙事流程自然引导修复电力、建造采集器、组装零件、准备火箭。

世界观：

- 人类消失后的核后世界 / 文明边缘废弃行星。
- 轨道自动化母舰“残骸”仍能运作。
- 机器文明自主演化。
- 数据核心保存旧人类智慧与指令权限。
- 觉醒者拥有自我意识，量产机是工具和消耗品。

长期目标：

- 寻找数据核心。
- 收集蓝图碎片和旧世界芯片。
- 解锁隐藏坐标。
- 培养觉醒者团队。
- 提升轨道站准备能力。
- 形成采矿、探索、战斗、快速回收等不同远征构筑。

UI 与美术：

- 地表 UI 参考《魔兽争霸》的清晰操作区。
- 轨道站 UI 参考《远行星号》的信息密度和功能性。
- 美术风格参考《远行星号》，避免通用科幻模板感。
- 美术资源以 AI 生成为主，但要服务单位识别、建筑识别和 UI 清晰度。

音频与反馈：

- 单位选择和指令确认。
- 建筑完成、资源不足、生产完成。
- 敌人接近、建筑受损、火箭完成。
- 扫描发现、蓝图获得、觉醒者发现、数据核心线索获得。

### 14.3 完成标准

- 玩家能理解主角、碎石、轨道母舰、数据核心和觉醒者体系。
- 首屏 UI 直接服务可玩流程。
- 游戏从轨道准备到地表远征再到回归成长具备完整体验。
- 美术、音频和叙事都服务核心循环，不制造额外玩法负担。

## 15. 设计边界

明确不做或谨慎处理的内容：

- 不做强制倒计时式压迫。
- 不做脱离主循环的小游戏。
- 不优先做高 APM 主动技能战斗。
- 不把轨道站做成线性升级树。
- 不让基地建设偏离返航和探索目标，避免变成纯自动化工厂游戏。
- 不让随机事件强迫玩家立即响应。
- 不把临时代码、本机绝对路径或个人 IDE 配置写入运行时代码。
