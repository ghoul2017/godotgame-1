# UI 美术设计文档

## 1. 依据、范围和修订规则

### 1.1 设计依据

本文只以以下文档为准：

- `docs/原始设计.txt`
- `docs/整体策划案.md`

UI 设计结论从上述两个源文档推导；实现代码、临时调试入口、旧 UI 草稿和分步实现状态只作为后续落地参考。若本文与上述两个源文档冲突，以上述两个源文档为准。

### 1.2 文档范围

本文负责 UI 的美术方向和资源标准：

- 主入口菜单的视觉设计。
- 轨道站全屏功能界面的视觉设计。
- 空投配置界面的视觉设计。
- 地表 HUD 和地表子面板的视觉设计。
- 火箭装载与回归结算界面的视觉设计。
- 通用按钮、面板、页签、列表、图标、提示、音效反馈规范。
- 新游戏和继续游戏进入正式流程所需的 UI 资源标准。

以下内容归入其他文档或流程：

- 编写玩法系统规则。
- 编写程序实现方案。
- 剧情内容、插图和故事事件设计。
- 调试入口和开发工具设计。
- 临时验证按钮、占位图和假数据管理。

### 1.3 修订规则

后续修改本文时按以下规则处理：

- 与 `原始设计.txt` 或 `整体策划案.md` 不一致的 UI 对象，用删除或重写完成修正。
- 文档结构本身代表设计结论；如果结构错了，优先重排章节。
- 轨道站是游戏循环内的永久成长层，由游戏流程进入。
- 主入口只表达继续游戏、新游戏、设置、退出。
- 新游戏后的正式内容按实际对象归入对应 UI、角色、建筑、事件和场景资源，不新增独立图片式入口页。

## 2. UI 总体定位

项目是 PC 单人生存探索 / RTS，2D 俯视视角。UI 需要服务“轨道准备 -> 地表远征 -> 火箭回归 -> 轨道成长”的循环。

整体参考：

- 地表 UI：参考《魔兽争霸》的清晰 RTS 操作区。
- 轨道站 UI：参考《远行星号》的信息密度和功能性。
- 美术风格：参考《远行星号》的旧工业、废土机械、低功耗终端感。

UI 美术关键词：

- 轨道残骸。
- 老旧工业终端。
- 末世机器文明。
- 高密度功能面板。
- 战术指挥界面。
- 回收材料拼接。
- 低功耗屏幕光。
- 旧世界数据噪声。

体验关键词：

- 清晰。
- 稳定。
- 可扫描。
- 有重量感。
- 信息服务决策。
- 地表操作低遮挡。
- 轨道规划高密度。

## 4. 全局视觉规范

### 4.1 色彩方向

整体色彩应是低饱和、多材质的工业科幻色系。推荐“暗金属底色 + 低亮度绿色 / 青色信息光 + 琥珀警示 + 少量数据紫”的组合。

| 用途 | 颜色语义 | 建议色值 |
| --- | --- | --- |
| 深层背景 | 轨道暗舱、废土夜色 | `#10130F` |
| 主面板底 | 氧化金属、旧终端外壳 | `#1D2420` |
| 次面板底 | 磨损铁灰 | `#2B322D` |
| 面板边线 | 暗钢边缘 | `#586058` |
| 主文字 | 旧屏幕白 | `#DDE0D2` |
| 次文字 | 灰绿说明文字 | `#9BA497` |
| 强调信息 | 信号青绿 | `#64B8AA` |
| 可执行状态 | 稳定系统绿 | `#83B66F` |
| 警告状态 | 琥珀黄 | `#D6A644` |
| 危险状态 | 锈红 | `#B85C4C` |
| 锁定状态 | 冷灰 | `#68706A` |
| 数据 / 蓝图 | 低饱和数据紫 | `#8A80BD` |

使用规则：

- 轨道站可使用更高信息密度和更多状态色。
- 地表 HUD 使用更克制的发光和对比，保留地图可读性。
- 数据紫用于纯净数据、蓝图、数据核心和旧世界信号。
- 错误、警告、可执行状态必须配合图标或文字，不只靠颜色。

### 4.2 材质方向

UI 面板应像“旧终端 + 金属框架 + 屏幕层”的组合。

推荐材质：

- 氧化金属板。
- 磨损漆面。
- 细噪点屏幕纹理。
- 低亮度扫描线。
- 机械铆钉和细窄分割线。
- 回收材料边框。
- 局部编号喷印。

纹理控制原则：

- 文字区域保持干净。
- 主操作按钮保持高识别度。
- 装饰纹理只增强世界观，不抢信息层级。

### 4.3 字体方向

中文主字体应清晰、偏工程终端感。标题可用更粗的工业黑体，正文使用高可读黑体，数值适合等宽或半等宽风格。

字号层级建议：

| 层级 | 用途 |
| --- | --- |
| 28-32 | 大页面标题、结算主标题 |
| 22-24 | 面板标题、页签当前项 |
| 18-20 | 常规列表、按钮、资源栏 |
| 14-16 | 标签、描述、限制原因 |
| 12-14 | 次级说明、调试标记、角标 |

### 4.4 形状语言

界面整体偏硬边、短倒角、模块化。

- 面板倒角控制在 2-6 px 的视觉感受。
- 按钮以矩形、切角和机械边框为主。
- 页签像终端模块插槽。
- 列表行保持规整，不做卡片堆叠式营销布局。
- 图标在 32 px 和 48 px 下保持清晰剪影。

## 5. 主入口菜单美术设计

### 5.1 定位

主入口菜单是游戏外壳，只承载存档和系统入口。它应像轨道自动化母舰的低功耗启动终端。

### 5.2 画面结构

建议布局：

```text
顶部或中央偏上：游戏标题
左中或中下：继续游戏 / 新游戏 / 设置 / 退出
右侧或底部：当前存档摘要
背景：轨道母舰残骸、废弃行星、低功耗屏幕光
```

按钮：

- 继续游戏。
- 新游戏。
- 设置。
- 退出。

新游戏创建正式游戏流程。轨道站由游戏流程进入，主入口表现为存档和开始游戏终端。

### 5.3 背景资源

主入口背景表现：

- 远处废弃行星轮廓。
- 轨道母舰残骸外部或内部终端。
- 低亮度绿色或琥珀系统光。
- 屏幕、线缆、维护臂等旧工业元素。

## 6. 轨道站界面美术设计

### 6.1 定位

轨道站是游戏循环中的永久成长层，是每轮远征的起点和终点。视觉上应是母舰后勤、交易、研发和空投准备终端。

### 6.2 固定骨架

```text
顶部状态栏：信用点 / 关键资源 / 提醒 / 远征摘要
左侧页签：库存 / 交易 / 研发 / 角色 / 空投
中央列表区：当前页主要对象
右侧详情区：选中对象说明、消耗、收益、限制
底部操作区：筛选、排序、确认、失败原因
```

### 6.3 页面视觉重点

库存页：

- 强调永久资产总览。
- 列表行显示图标、名称、分类、数量、重量、价值。
- 详情区显示用途、可交易、可研发、可空投状态。

交易页：

- 像轨道补给和自动交易终端。
- 条目表达“消耗 -> 获得”。
- 信用点图标应像轨道结算凭证。

研发页：

- 像旧世界蓝图解码和协议解锁。
- 使用项目列表，不做树状强制路线。
- 已完成研发保留为审计记录。

角色页：

- 觉醒者使用头像、姓名、背景、技能摘要。
- 量产机使用平台图标、数量、状态和可空投能力。
- “灵巧”和“碎石”应有明显个人识别特征。

空投页：

- 表现为下一轮远征准备入口。
- 显示已知坐标、可用空投舱、可用角色和关键资源摘要。

## 7. 空投配置界面美术设计

### 7.1 定位

空投配置界面表现为轨道投送审计终端，让玩家清楚看见坐标、空投舱、单位、物资、容量和风险的取舍。

### 7.2 布局

```text
顶部状态栏：坐标 / 空投舱 / 重量 / 格位 / 单位容量
左侧：坐标列表和空投舱列表
中央：可选单位、物资、装备、芯片、工具
右侧：当前装载清单
底部：校验提示、取消、确认空投
```

### 7.3 视觉重点

- 坐标卡片显示区域类型、风险、资源标签和可重复访问状态。
- 空投舱卡片显示图标、示意图、载重、格位、单位容量和前置条件。
- 装载清单像货舱审计票据，按觉醒者、量产单位、物资、装备、芯片分组。
- 容量条同时显示数值、刻度和状态色。
- 确认反馈要短促、明确，像投送系统完成校验。

## 8. 地表 HUD 美术设计

### 8.1 定位

地表 HUD 是玩家进行 RTS 操作的主界面，服务探索、建造、生存、战斗和火箭返航。

### 8.2 固定骨架

```text
顶部：资源栏、电力状态、当前提醒
中央：地表地图、单位、建筑、资源点
左下：小地图
底部中央：单位 / 建筑选择信息面板
右下：命令按钮区
右侧：消息和事件提示
```

### 8.3 区域视觉重点

顶部资源栏：

- 显示金属、硅、稀土、能源块、废料等关键资源。
- 数值适合等宽显示。
- 资源不足时对应图标和数字高亮。

小地图：

- 显示已探索、未探索、当前视野、资源点、废墟、特殊信号和威胁。
- 战争迷雾使用低透明暗色遮罩。

选择信息面板：

- 单单位：头像、名称、耐久、能源、库存、当前指令、行为模式、装备摘要。
- 多单位：头像网格、数量、类型分组、共同指令。
- 建筑：图标、名称、耐久、电力、库存、生产状态。

命令按钮区：

- 使用图标优先。
- 覆盖移动、采集、搬运、建造、修理、攻击、护卫、扫描、骇入、回维修点、取消。
- 禁用状态显示原因。

消息区：

- 普通消息低干扰。
- 重要发现保留在列表。
- 威胁提示清晰但不全屏闪烁。

## 10. 地表子面板美术设计

### 10.1 建造菜单

建造菜单从右下命令区展开，按建筑分类显示：

- 基础设施。
- 生产。
- 电力。
- 防御。
- 火箭。

建筑图标应表现建筑用途。放置预览显示可放置、阻挡、资源不足和前置状态。

### 10.2 生产和电力面板

生产面板显示配方、队列、输入、输出和电力需求。

电力面板显示发电量、耗电量、储能、停机建筑和电力状态。

两者视觉上都应像地表临时基地的工程终端，信息密度低于轨道站，避免遮挡地表局势。

### 10.3 探索 / 地图界面

地图界面显示区域、战争迷雾、资源点、废墟、特殊信号和威胁。图例清晰，信号和废墟要有旧世界数据残留感。

### 10.4 行为模式面板

行为模式面板显示固守、游击、采集优先、护卫、撤退维修。图标应表达行为倾向，让玩家快速理解单位自动行为。

## 11. 火箭装载和回归结算美术设计

### 11.1 火箭装载界面

火箭装载界面是远征结束前的取舍界面。

布局：

```text
顶部：火箭状态、载重、超载风险
左侧：可带回内容
中央：当前货舱清单
右侧：遗留内容预览
底部：保存装载、确认发射、返回地表
```

视觉重点：

- 货舱清单像回归审计单。
- 超载提示清楚显示风险。
- 遗留内容用封存或留置标记表达。
- 关键物、芯片、蓝图、觉醒者优先可识别。

### 11.2 回归结算界面

回归结算表现“写回轨道永久层”。

结算列：

- 带回物资。
- 带回芯片。
- 带回蓝图。
- 觉醒者回归。
- 损失单位和装备。
- 遗留内容。
- 新发现坐标和线索。

写入轨道按钮应有明确确认感，反馈短促，不做胜利庆典式夸张效果。

## 12. 通用组件规范

### 12.1 面板

面板由外框、内底、标题条组成。

- 主面板：页面核心区域。
- 详情面板：选中对象说明。
- 弹窗面板：确认和错误。
- HUD 面板：地表操作区，遮挡少。

### 12.2 按钮

按钮状态：

- 默认。
- 悬停。
- 按下。
- 禁用。
- 危险确认。
- 主要确认。

按钮文字保持短，复杂说明放在详情区或提示区。

### 12.3 页签

轨道站页签固定为库存、交易、研发、角色、空投。

当前页签高亮；锁定页签显示锁定图标和原因。页签图标必须表达模块语义。

### 12.4 列表行

列表行包含图标、名称、分类、数量 / 消耗 / 状态、右侧角标。高度保持一致，便于扫描。

### 12.5 图标

图标需要覆盖道具、单位、建筑、技能、事件、空投舱、命令、状态和页签。

图标风格：

- 清晰剪影。
- 低饱和金属底。
- 少量状态色。
- 32 px 下能识别分类。

### 12.6 容量条和进度条

用于空投重量、格位、单位容量、火箭货舱、电力和生产。

容量条应显示：

- 当前值。
- 上限。
- 状态色。
- 刻度或文字。

## 15. 分阶段 UI 美术交付顺序

分阶段交付按最终系统形态推进。每一步资源都应是最终系统的一部分。

1. 基础工程、输入和场景流程：主入口、轨道站、地表 HUD、回归结算的基础 UI 皮肤和按钮。
2. 统一数据、道具、库存和存档结构：首批道具、单位、建筑、空投舱、技能、事件图标和识别资源。
3. 轨道站主框架：轨道站页签、面板、列表行、按钮状态和信息密度基准。
4. 空投配置与远征创建：空投舱、坐标、容量提示、装载清单和确认反馈。
5. 地表 RTS 控制与单位系统：单位精灵、头像、选择圈、指令光标、移动目标反馈和编组反馈。
6. 地表资源、建造、生产和电力系统：资源点、建筑、建造预览、施工状态、电力状态和生产反馈。
7. 探索、战争迷雾、扫描和区域内容：战争迷雾、扫描效果、废墟、特殊信号和区域标记。
8. 战斗、行为模式和防御系统：武器效果、命中特效、行为模式图标、防御状态和威胁提示。
9. 角色成长、觉醒者、AI 芯片和改装：觉醒者头像、技能图标、芯片图标、改装件图标和改装预览。
10. 火箭建造、装载、回归和结算：火箭阶段外观、货舱 UI、超载提示、发射反馈和结算资源。
11. 程序生成、随机事件和复现调试：生成调试可视化、事件图标、区域标记和种子日志展示。
12. 长期目标、美术音频和完整内容集成：统一主角、碎石、母舰、数据核心等关键视觉，并整合全局 UI 和音频反馈。

## 16. 音效反馈方向

UI 音效应短、干、偏机械终端。

首批音效：

- 页签切换。
- 按钮确认。
- 按钮失败。
- 列表选择。
- 交易成功。
- 研发解锁。
- 空投确认。
- 回归写入完成。
- 地表指令下达。
- 资源不足提示。

## 17. 美术验收清单

每次 UI 资源或界面交付时检查：

- 是否服务当前开发步骤的正式系统。
- 是否符合旧工业、末世机械和母舰终端气质。
- 是否能在 PC 16:9 下保持可读。
- 是否每个正式 ID 都有独立可识别图标或图像资源。
- 是否资源路径与推荐目录一致。
- 是否轨道站信息密度足够且不混乱。
- 是否地表 HUD 清晰且低遮挡。
- 是否错误、警告、可执行、锁定、已完成状态清楚。
- 是否确认前能看见消耗、收益、限制和失败原因。
- 是否资源被实际界面或主题引用。

## 18. 后续风险

需要持续关注：

- 主入口功能外溢，削弱继续游戏和新游戏入口。
- 轨道站信息密度不足，变成大图展示页。
- 地表 HUD 遮挡地图和单位。
- 图标只做分类，不为正式对象提供独立识别。
- 空投配置没有表达重量、格位和单位容量取舍。
- 火箭装载没有表达带回和遗留取舍。
- 回归结算只显示收益，缺少损失、遗留和发现复盘。
- 调试入口混入正式 UI。
